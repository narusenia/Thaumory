# Thaumory 要件定義

Thaumcraft（特に TC2）にインスパイアされた、Minecraft の魔術 Mod。
「あらゆるものはアスペクトでできている」という世界観を核に、アスペクトの抽出・魔法陣・ポーション調合・魔術工学を1つの体系で繋ぐ。

- 種別: 個人の趣味プロジェクト
- 対象: Minecraft 26.3 / Java 25 / Architectury（Fabric がプライマリ、NeoForge は M4 で追加）
- ライセンス: 本体 MPL-2.0 / API（`thaumory-api`）MIT / アセットは別途（CC BY-NC-SA 想定）
- 配布: Modrinth・CurseForge

---

## 1. 柱

| 柱 | 内容 |
|---|---|
| アスペクト体系（核） | 全アイテムがアスペクトの構成を持つ。Primal 6種 + 複合12種 |
| リサーチ | 発見型（スキャン・試行の記録・ヒント）+ 進行ツリー（本の章） |
| 魔術工学 | Essentia の抽出・貯蔵・輸送。手動 → 配管 → 無線の段階的アンロック |
| 魔法陣 | Core + Rune + 紋様。設置効果とクラフト（注入）の両方を担う |
| ポーション調合 | アスペクトをベクトルとした、Potion Craft 風のマップ調合 |
| 代償 | 局所的な Flux（チャンク単位、拡散しない） |

## 2. アスペクト

### 2.1 Primal（3組の対立ペア）

六角形に 60° 刻みで配置する。並び順は Ignis → Aer → Vita → Aqua → Terra → Mors。

| アスペクト | 方向 | 対 |
|---|---|---|
| Ignis（火） | 0° | Aqua |
| Aer（風） | 60° | Terra |
| Vita（生） | 120° | Mors |
| Aqua（水） | 180° | Ignis |
| Terra（土） | 240° | Aer |
| Mors（死） | 300° | Vita |

### 2.2 複合（12種）

- 隣り合う Primal（60°差）と、1つ飛ばしの Primal（120°差）の組み合わせが複合アスペクトになる
- 正反対の Primal（180°差）は組み合わせられない。打ち消し合って Flux になる

| 種類 | 組み合わせ | 名前 | 意味 | 対 |
|---|---|---|---|---|
| 隣 | Ignis + Aer | Lux | 光 | Umbra |
| 隣 | Aer + Vita | Arcanum | 魔力 | Vinculum |
| 隣 | Vita + Aqua | Herba | 植物 | Bellum |
| 隣 | Aqua + Terra | Umbra | 闇 | Lux |
| 隣 | Terra + Mors | Vinculum | 束縛・封印 | Arcanum |
| 隣 | Mors + Ignis | Bellum | 戦・破壊 | Herba |
| 1つ飛ばし | Ignis + Vita | Bestia | 獣 | Venenum |
| 1つ飛ばし | Aer + Aqua | Tempestas | 嵐・天候 | Metallum |
| 1つ飛ばし | Vita + Terra | Ordo | 秩序 | Chaos |
| 1つ飛ばし | Aqua + Mors | Venenum | 毒 | Bestia |
| 1つ飛ばし | Terra + Ignis | Metallum | 金属 | Tempestas |
| 1つ飛ばし | Mors + Aer | Chaos | 混沌 | Ordo |

- 名前はラテン語で統一する
- アイコン: アスペクトの名前の前には、そのアスペクトのアイコンを付ける（ツールチップ・HUD・本・チャットのどこでも）。アイコンは白の図形をアスペクトの色で塗る
  - 置き場所: `assets/<namespace>/textures/gui/sprites/aspect/<path>.png`（GUI のアトラス）。アドオンのアスペクトは、同じ場所にアイコンを置く
  - 未判明のアスペクトは、共通の「未知」のアイコンをアスペクトの色で出す（絵柄で正体が分からないように）
- 名前の演出: 判明したアスペクトの名前は、アスペクトごとに決めた文字の演出（§7.6）で描く。演出はアスペクトの定義に持たせ（API）、アドオンのアスペクトも選べる。指定しなければ演出なし
  - 初期値: にじみ = Ignis・Venenum、波 = Aer・Aqua、脈動 = Vita・Herba・Umbra、震え（弱）= Mors・Bellum、震え（強）= Tempestas・Chaos、光の筋 = Lux・Metallum、揺らめき = Arcanum、なし = Terra・Vinculum・Ordo・Bestia
- さらに上の階層は、アドオンも API 経由で追加できる

#### 第 3 層と Nihil（M2-13・M2-32・M5）

- 第 3 層: 複合 + 複合、または複合 + Primal でできるアスペクトを 12 前後足す（合計 30 あまり）。Primal まで分けたときに対（180°差）が 1 組も入らない組み合わせだけ（§2.1 の打ち消しの決まりとそのまま両立する）
  - 中盤以降の品（ネザー・エンド・魔術の品）に多く含まれる。汚染のアスペクト（M2-13）が最初の 1 つ
  - 登録するとき、Primal まで分けて対が入っていれば受け付けない（アドオンの第 3 層も同じ）
  - 汚染（M2-13）: Sordes（穢れ）= Venenum + Vinculum。縛られて淀んだ毒。Primal は Aqua・Terra・Mors で、Ignis・Aer・Vita を含むアスペクトと打ち消し合う。対は Arcanum + Bestia（M2-32 で登録されれば対になる）。色は濁った紫、名前の演出は震え（弱）
    - 含む品: 汚染された土・汚染された石 = Terra 4 + Sordes 2、Flux の結晶 = Sordes 4
  - 残りの第 3 層（M2-32）: 対になる 6 組（Sordes を含めて 12）。どの組も、両方が登録されているので互いの対になる
    - 品の値は各 3〜6 品（判明に 3 種類が要るため）。今の値の一部を置き換え、合計の量は大きく変えない
    - ヒントは対ごとに 1 つ。対の両方を判明させると現れる

| 対 | アスペクト | 構成 | 意味 | 色 | 名前の演出 |
|---|---|---|---|---|---|
| 1 | Sordes | Venenum + Vinculum | 穢れ | 濁った紫 | 震え（弱） |
| 1 | Anima | Arcanum + Bestia | 魂・生気 | 淡い桃 | 脈動 |
| 2 | Aurora | Lux + Arcanum | 暁・魔力の光 | 薄紅の金 | 光の筋 |
| 2 | Vesper | Umbra + Vinculum | 宵・縛る闇 | 群青 | 揺らめき |
| 3 | Abyssus | Umbra + Mors | 深淵・虚空 | 黒に近い紺 | 脈動 |
| 3 | Caelum | Lux + Vita | 天 | 空色 | 波 |
| 4 | Sigillum | Vinculum + Metallum | 封印 | 鈍い金 | なし |
| 4 | Solutio | Arcanum + Tempestas | 解放・解き放つ | 淡い青緑 | 波 |
| 5 | Tartarus | Bellum + Ignis | 冥府・ネザー | 赤黒 | にじみ |
| 5 | Fons | Herba + Aqua | 泉 | 青緑 | 波 |
| 6 | Peregrinum | Chaos + Tempestas | 異界・エンド | 淡い紫 | 震え（強） |
| 6 | Artificium | Ordo + Metallum | 仕組み・機構 | 真鍮 | なし |

  - 物語の鍵になるもの（封印・虚空など）と、光と闇の素材（§17.9）に使うものを含める
  - 一覧（名前・組み合わせ・意味・対）は M2-32 に着手するときに決める。ポーション調合（M3）の前に入れる
- Nihil（無）: 六角形の中心にあたる 7 つ目の特別なアスペクト。どの Primal の組み合わせでもない。封印の間の儀式（§17.8）で判明する
  - 手に入れ方は道で違う（光は封瓶、闇は虚の炉。§17.9）。使う品は両方の道で同じ（§17.10）

### 2.3 アイテムのアスペクト定義

- 手動定義（datapack JSON）: 自然物などの基本素材 200〜300 程度。タグでの一括指定に対応する
  - 置き場所: `data/<namespace>/thaumory/item_aspects/*.json`
  - 形式: `{"values": [{"target": "minecraft:oak_log", "aspects": {"thaumory:herba": 4}}]}`。`target` の先頭に `#` を付けるとアイテムタグ
  - `aspects: {}` は「明示的にアスペクトなし」を表す（自動推定の対象からも外す）
  - 優先順位: アイテムの直接指定 > タグ。同じ対象が複数ある場合は、上位の datapack が勝つ。同じ datapack の中ではファイル ID 順で後のものが勝つ。同じパスのファイルは上位の datapack が丸ごと置き換える（バニラと同じ）
  - 不明なアスペクト・アイテムを含む行は、警告をログに出して飛ばす
- 手動定義の量の目安（合計）: ありふれた 8〜16、普通 16〜32、貴重 32〜64、非常に貴重 64〜128。通常のプレイで手に入らないもの・スポーンエッグ・中身がコンポーネントで変わるもの（ポーション、エンチャントの本、記入済みの地図など）は `{}`
- 定義のないアイテムは、レシピから「何でできているか」を推定する（減衰させない。溶かしたときの損失は Crucible が受け持つ。§3）
  1. 材料のアスペクトを合算する
  2. 完成品の個数で割る
  3. アスペクトは最大6種類。超えた分は量の少ないものから削る
  4. 計算中は 1000 倍の精度で持ち、最後に1回だけ切り捨てる。0 になったアスペクトは消す
  - 複数のレシピがある場合は、合計量が最小のレシピを採用する（同点ならレシピ ID 順）
  - かまど系のレシピは Ignis +1
  - 完成品が光を出すブロック（置いたときの既定の状態で明るさが 1 以上。松明・ランタン・シーランタンなど）なら Lux +1。レシピの種類を問わず、ワールド内の変化にも適用する
  - 対象のレシピ: 作業台（定形・不定形・変換）、かまど系4種、石切台、鍛冶台のアップグレード（テンプレートも材料に含める）。特殊レシピ（花火・旗の複製・修理など）と醸造台は対象外
  - ワールド内の変化もレシピとして扱う: 酸化（Aqua +1）、コンクリートの固化（Aqua +1）、泥（Aqua +1）、サンゴの死滅（Mors +1）、カボチャのくり抜き、金床の損傷（Chaos +1）
  - 材料の欄に複数の候補がある場合は、合計量が最小の候補を使う（同点ならアイテム ID 順）。完成品そのものは材料の候補にしない
  - 材料が戻ってくる場合（牛乳入りバケツ → 空のバケツ）は、戻ってくるアイテムのアスペクトを差し引く。バケツ入りのものは中身だけを手動定義する
  - 計算の手順: まず段階的に確定させる（1巡目は手動定義だけが確定した状態から始め、各巡で「材料がすべて確定済みのレシピ」だけを使って未確定のアイテムを計算し、巡の終わりにまとめて確定させる）。その後、どのレシピでも完成品の値が材料より高くならなくなるまで、安い経路で値を下げる（0.1 未満の差は丸め誤差として無視する）。どの巡でも確定しなかったアイテムはアスペクトなし
  - これにより、どのレシピも「作って溶かすと得をする」ことはない（圧縮・解凍、染め直し、形違いの素材の循環を含む）
  - 他 Mod のレシピの種類は、API のレシピアダプター（§12 の 9）で対象に加えられる。レシピ以外の変化は、同じ API の推定ソースで加えられる
  - `/thaumory aspects report` で、手動定義が必要なアイテム・材料が決まらないアイテム・得をするレシピ・大きく値が下がったアイテムの一覧を書き出せる
- 推定はサーバーの起動時と `/reload` の完了後に計算し、クライアントへ同期する

## 3. Crucible（るつぼ）

- 作り方: 作業台で、大釜 + 金インゴット（不定形）
- 水を入れ、下に熱源を置くと稼働する
  - 熱源はブロックタグ `thaumory:crucible_heat_sources`（初期: 火・魂の火・溶岩・マグマブロック・焚き火・魂の焚き火）。`lit` を持つブロックは火がついているときだけ
  - 水と熱源がそろってから沸騰するまで少し待つ（初期 5 秒）。熱源か水が無くなると冷める
- 水は大釜と同じ 3 段階。水入りバケツで満杯、水入りの瓶で +1。溶かした Essentia の合計 100（初期値）ごとに 1 段階減る。水が尽きると溶けなくなるが、中身は残る。バケツで水を汲むことはできない
- アイテムを投げ入れると Essentia に溶け、混ざった状態で溜まる。沸騰している間、中のアイテムを一定間隔（初期 0.25 秒）で 1 個ずつ溶かす。アスペクトのないアイテムは溶けずに残る
- 容量の上限（初期 500）を超えた分は、1:1 でそのチャンクの Flux として溢れる。入りきらないときは、そのアイテムの量の多いアスペクトから先に入れる
- 溶かしたときに得られる量: 手動定義のアイテム（素材）は 100%、レシピから推定されたアイテム（完成品）は 75%（アスペクトごとに切り捨て）。完成品を溶かすより素材を溶かすほうが得になるようにする
- Crucible を壊すと、中身はすべて Flux になる
- 中身は魔術のルーペを持って Crucible を見ると画面に表示される（未判明のアスペクトは揺らめく紋字。§6.1）
- 容量・割合・沸騰までの時間・溶かす間隔・水 1 段階あたりの量・打ち消しの間隔と量は `data/thaumory/thaumory/crucible.json` で調整でき、上位の datapack が丸ごと置き換える
- 正反対の Primal を含むアスペクトが同時にあると、少しずつ打ち消し合って Flux が出る（複合アスペクトも、構成要素で判定する）
  - 沸騰している間だけ起きる。一定間隔（初期 1 秒）ごとに、打ち消し合う組み合わせそれぞれの両方から同じ量（初期 1。どちらかの残りが少なければその量）ずつ減り、減った分は 1:1 でそのチャンクの Flux になる。1 つのアスペクトが複数の組み合わせに入っていれば、その分だけ減る
  - 打ち消しのたびに紫のパーティクルが出る。ルーペで見ると HUD に警告が出る
- 取り出し: 瓶（Jar）を使う。ラベル付きの瓶はそのアスペクトだけを、ラベルなしの瓶は一番多いアスペクトを取り出す（§3.1）
- 錬金術: 必要なアスペクトが揃った状態で触媒を投げ入れると、アスペクトを消費してアイテムが完成する（Rune の素材、チョーク、装備の素材など）
  - レシピは `data/<namespace>/recipe/*.json` に `"type": "thaumory:alchemy"` で書く。形式: `{"type": "thaumory:alchemy", "catalyst": "minecraft:stone", "aspects": {"thaumory:terra": 8}, "result": {"id": "thaumory:blank_rune"}}`（`catalyst` はバニラの材料と同じ書き方で、タグも使える）
  - 沸騰している間、溶かす順番が来た触媒 1 個について判定する。成立すれば、溶かす代わりにアスペクトと触媒 1 個を消費し、完成品を Crucible の外へ飛ばす。足りなければ普通に溶ける
  - 1 つのレシピが打ち消し合うアスペクトを同時に要求してはいけない（集めている間に減ってしまう）。組み込みのレシピは datagen で検査する
  - 同じ触媒で複数のレシピが成立するときは、必要なアスペクトの合計が多いほうを使う（同じならレシピ ID 順）
  - 錬金術レシピもアスペクトの推定に使う（触媒 + 必要なアスペクト）
  - 章による開放（§6.2）は M1-10 で入れる。それまではすべてのレシピが使える
  - 初期レシピ: 空の Rune（石 + Arcanum 4・Aqua 4）、基本のチョーク（粘土玉 + Arcanum 2・Aqua 4）、増幅（基本のチョーク + Ignis 8）、延長（+ Aer 8）、節約（+ Vinculum 4）、安定（+ Ordo 4）
- 調合モード: ポーション調合（M3、§9）もこの装置で行う

### 3.1 瓶（Jar）とラベル

- 瓶は置けるブロック。壊すと中身ごとアイテムになる（スタックしない）。レシピ: ガラス 5（U 字）+ 木のハーフブロック（蓋、どの木でもよい）
- 容量は 64（`data/thaumory/thaumory/jar.json` の `{"capacity": 64}`）
- 汲む: 瓶を持って Crucible か置いた瓶を右クリックすると、手の瓶に 1 種類のアスペクトを入るだけ移す。ラベル付きならそのアスペクト、ラベルなしなら相手の中で一番多いアスペクト
- 注ぐ: スニーク + 右クリックで、手の瓶の中身を注ぐ
  - Crucible へは全部注ぎ、容量を超えた分は Flux になる（水は使わない）
  - 置いた瓶へは入るだけ注ぎ、残りは手の瓶に残る。ラベル付きの瓶にはそのアスペクトだけが移る
  - 陣の Core へ注ぐ操作も同じにする（M1-19）
- ラベル: 紙 + イカスミ で 4 枚。置いた瓶をラベルで右クリックすると、中のアスペクトが 1 種類のときだけ、そのアスペクトのラベルが貼られる（ラベルは 1 枚消費）。スニーク + 素手で剥がす（ラベルは戻らない）
- ラベルなしの瓶で正反対のアスペクトが混ざると、その瞬間に、どちらかが尽きるまで打ち消し合う。減った分はその場所のチャンクの Flux になる
- 中身は、手に持った瓶はツールチップ、置いた瓶はルーペで見ると HUD に出る。置いた瓶には液面を描く（高さ = 量、色 = 各アスペクトの色を量の割合で混ぜた色）

## 4. 魔法陣

### 4.1 Core とスロット

- Core ブロックに Rune を3つ挿す（上のランクの Core は 4〜5 つ。§4.6）
  - 作り方: 作業台で、中央に空の Rune、上下左右に金インゴット、四隅に石レンガ
  - 挿す: アスペクトの Rune を持って右クリックすると、空いている一番若いスロットに入る（1 → 2 → 3）。空の Rune は挿せない
  - 抜く: スニーク + 素手で右クリックすると、最後に埋まっているスロットから抜ける。GUI は開かない
  - Core を壊すと、挿した Rune は落ちる
  - 置く: 置いた面に描かれる（床・壁・天井。§4.3）。しっかりした面にだけ置ける。支えのブロックが無くなると壊れる（壊したときと同じく Rune は落ち、中身は Flux になる）。台座（§10.1）は床の Core にだけ組み込める
  - 見た目: 地面に直接描いた紋様のような薄いブロック（下地の板は無い）。Rune が無いときは中央に小さな円だけがあり、Rune を 1 つ挿すごとにその外側に円が 1 つ現れ、3 つで完成する。各円はその Rune のアスペクトの色で光り、周りに同じ色の淡い光がにじむ（暗い所ほど目立つ）。隣り合う円は逆向きにゆっくり回る
- スロット1・2: 効果の種類（順不同）
- スロット3: パラメータ（チャンネル・反転・対象・フィルタ・モード）。空でもよく、空の場合はその効果のデフォルトの挙動になる
- 未定義の組み合わせ: 不発 + Flux の発生
  - リングが 1 つ以上成立し、Rune が 2 つ以上挿してあるのに組み合わせが定義されていないとき、起動（持続型）・発動（起動型）を試みると、Core のチャンクに Flux が出る（`circle.json` の `undefined_flux`、初期 5）。Essentia は減らない
  - スロット 1・2 が定義済みでも、スロット 3 が `slot3` の一覧に無ければ未定義として扱う
  - リングが無い・Rune が 2 つ未満のときは陣として数えず、Flux も記録も無い
  - 杖で試した人の知識に、その組み合わせを失敗として記録する（§6.3。成功済みなら成功のまま）
  - 紫のパーティクルと音を出す
- Core の Essentia: 陣が消費する Essentia を Core に溜める
  - 瓶を持ってスニーク + 右クリックで注ぐと、挿した Rune のアスペクトだけが入る。アスペクトごとに容量 64（`circle.json` の `essentia_capacity`）。入らなかった分は瓶に残る
  - 瓶で右クリックすると汲める（ラベル付きならそのアスペクト、ラベルなしなら一番多いアスペクト）
  - アスペクトごとに分けて持つので、打ち消しは起きない（灯火のように正反対のアスペクトを使う組み合わせがあるため）
  - Rune を抜いても、そのアスペクトの Essentia は残る（汲み出せるが、新しくは注げない）
  - Core を壊すと、中身はすべてそのチャンクの Flux になる。ルーペで Core を見ると中身も出る
- 組み合わせの定義: `data/<namespace>/thaumory/circle/*.json` に 1 ファイル 1 効果で書く。上位の datapack の同じパスのファイルが丸ごと置き換える。同じ組み合わせが複数のファイルにあれば、ファイル ID 順で後のものが勝つ
  - 形式: `{"effect": "thaumory:light", "runes": ["thaumory:lux", "thaumory:ignis"], "slot3": ["none", "thaumory:umbra"], "mode": "sustained", "interval": 200}`
  - `effect`: コードで登録した効果の ID（§12 の 2）。`runes`: スロット 1・2（順不同）。`slot3`: 許すスロット 3 の一覧（`"none"` は空、`"any"` はどのアスペクトでもよい）、または `"any"` だけ（どのアスペクトでもよく、空は不可）。一覧に無いスロット 3 は未定義の組み合わせ
  - `settings`: 効果ごとの数値（省略可）。例: `{"flux_per_second": 0.5}`。効果は書かれていない値に初期値を使う
  - `mode`: `"triggered"`（起動型、`cost` が N）または `"sustained"`（持続型、`interval` が消費の間隔の tick）
  - 不明な効果・アスペクトを含むファイルは、警告をログに出して飛ばす
- 起動と停止: 杖で行う（§7.1）。デバッグコマンド `/thaumory circle <pos> start|stop|trigger` でも行える
  - 陣が動くには、リングが 1 つ以上成立していて、組み合わせが定義されていること
  - 持続型が動いている間に陣が崩れる（リングが 0 になる、Rune が変わって組み合わせが変わる・未定義になる）と停止する

### 4.2 Rune

- 恒久的な鍵。消費されない
- Crucible の錬金術で「空の Rune」を作り、任意のアスペクトの Essentia を注ぐとそのアスペクトの Rune になる（アスペクトごとのレシピは不要）
  - 注ぎ方: 利き手に瓶、オフハンドに空の Rune を持ってスニーク + 右クリックする（空中でも、ブロックを狙っていてもよい。Crucible と置いた瓶を狙っているときは、そちらへ注ぐ操作が優先される）
  - 瓶のラベルのアスペクト、ラベルなしなら一番多いアスペクト（汲むときと同じ選び方）を消費し、空の Rune 1 つがそのアスペクトの Rune になる。できた Rune はインベントリに入り、入らなければ足元に落ちる
  - 必要量は初期 16。`data/thaumory/thaumory/rune.json` の `{"cost": 16}` で変えられ、上位の datapack が丸ごと置き換える。足りなければ何も消費せず、必要量をアクションバーに表示する
- Rune は 1 種類のアイテムで、アスペクトをコンポーネントに持つ。アドオンのアスペクトにも自動で対応する
  - 見た目はアスペクトの色で塗り分ける。ツールチップにアスペクトを出す（未判明は揺らめく紋字）
  - クリエイティブタブには、登録されたすべてのアスペクトの Rune を並べる
  - Rune そのもののアスペクトはなし（Crucible で溶けない）

### 4.3 周囲の陣（紋様）

- リング（M2-35 で四角から円に変える）: Core を中心とした円。n 番目のリングは半径 2n − 1（1・3・5・7・9。上のランクの Core ほど外まで。§4.6）で、Core からの距離が半径 ± 0.5 未満のマスの並び。リングの間は 1 マス空く。1 番目は今と同じ 3×3 の外周。円のマスをすべて基本の線で描くと成立する。一部が欠けたリングは成立せず、その外側のリングも無効になる
  - リングの間や外にある紋様は、リングの判定には関係しない（飾りに描いてよい）
  - 見た目: 地面は描いたチョークのマスのまま（段差は点で切れて見える）。円の形は、動いている陣の上に浮かぶ光る紋（§4.6）で見せる。滑らかな白い円を重ねる案は、修飾の色が見えにくくなるのでやめた
  - 紋様は Core と同じ面に描く（床の陣なら同じ地面の上、壁の陣なら同じ壁の同じ向きの面、天井の陣なら同じ天井）。向きの違う紋様・面から浮いた紋様は数えない
  - 壁と天井（M2-16）: 床・壁（東西南北の 4 方向）・天井のどの面にも Core とチョークを描ける。リングはその面の上の円で、節点は面の上下左右（東西南北にあたる）のマス。範囲は床と同じく Core を中心とした立方体
  - 「陣の前」= 陣の描かれた面から離れる向き（床なら上、天井なら下、壁なら壁から手前）
  - 節点以外のマスに描いた修飾は線として数える。修飾の効果は無く、ルーペ（§7.2）で「無視された修飾」として示す
- 節点: 各リングの東西南北の4か所に修飾の紋様を描く。リング3つなら最大12個
  - 節点は円の東西南北のマス（Core から真東・真西・真南・真北に、そのリングの半径だけ離れたマス）。そこには基本の線の代わりに修飾の紋様を描き、修飾のマスもリングの一部として数える
- リングの数 → 効果範囲（初期: r1 = 半径4、r2 = 半径8、r3 = 半径16。`circle.json` の `ring_radius`）
- スキャン範囲は最大 11×11（ランク 1。上のランクは §4.6 の表のとおり）

| 紋様 | 効果 | 副作用 |
|---|---|---|
| 増幅 | 強度が上がる | 消費量が増え、不安定度が上がる |
| 延長 | 範囲が広がる | 消費量が増える |
| 節約 | 消費量が減る | 強度が下がる |
| 安定 | 不安定度が下がる | 節点を1つ占有する |

- 修飾の倍率: 強度・範囲・消費量のそれぞれについて、倍率 = 1 + 節点の紋様ごとの値の合計（下限 0.25）。初期値は増幅 強度 +0.5・消費 +0.5、延長 範囲 +0.5・消費 +0.25、節約 消費 −0.25・強度 −0.25
- 範囲 = リングの数で決まる半径 × 範囲の倍率。強度の使い方は効果ごとに決める

- 不安定度が閾値を超えると、発動のたびに確率で Flux が出る
  - 不安定度 = 成立したリングの節点に描いた紋様ごとの値の合計（0 未満にはならない）。初期値は増幅 +2、安定 −3、延長・節約 0
  - 閾値（初期 3）を超えた分（超過 = 不安定度 − 閾値）で Flux の確率と量が決まる
  - 判定は Essentia を払うたび: 起動型は発動ごと、持続型は消費の間隔ごと（起動時の 1 回目も含む）
  - 確率 = 超過 × `chance_per_point`（初期 0.2、最大 1）、量 = 超過 × `flux_per_point`（初期 2）。Core のチャンクに出る。効果そのものは普通に働く
  - `circle.json` の `"instability_flux": {"chance_per_point": 0.2, "flux_per_point": 2}`
- 陣の判定は一定の間隔（初期 2 秒）で Core が周囲を調べ直す
- 判定の間隔・不安定度の閾値・不安定度による Flux・未定義の組み合わせの Flux・リングごとの半径・Core の容量・紋様ごとの値は `data/thaumory/thaumory/circle.json` に書き、上位の datapack が丸ごと置き換える。紋様はブロック ID で指定するので、アドオンの紋様にも値を付けられる。書かれていない値は 0
  - 形式: `{"scan_interval": 40, "instability_threshold": 3, "instability_flux": {"chance_per_point": 0.2, "flux_per_point": 2}, "undefined_flux": 5, "child_instability": 1, "ring_radius": [4, 8, 16], "essentia_capacity": 64, "stone_radius": 4, "patterns": {"thaumory:amplifying_pattern": {"instability": 2, "strength": 0.5, "cost": 0.5}, "thaumory:extending_pattern": {"range": 0.5, "cost": 0.25}, "thaumory:economizing_pattern": {"cost": -0.25, "strength": -0.25}, "thaumory:stabilizing_pattern": {"instability": -3}}}`
- 紋様として数えるブロックはブロックタグ `thaumory:circle_patterns` で決める（アドオンの紋様はこのタグに入れる）。基本の線は `thaumory:chalk_line`

### 4.4 Essentia の消費

- スロットに入れたアスペクトそのものを消費する。数量は JSON で定義する
- 起動型: 1回ごとにスロット1・2のアスペクトを N ずつ、スロット3のアスペクトを 1 消費する
  - N は `cost` × 消費の倍率を四捨五入した数（最低 1）。スロット 3 の 1 は倍率をかけない
  - 足りなければ何も消費せず、発動しない
- 持続型: 一定の間隔（例: 10秒）ごとに、スロット1・2のアスペクトを 1 ずつ消費する
  - 間隔は `interval` ÷ 消費の倍率（四捨五入、最低 1 tick）。起動した時点で 1 回目を消費する
  - 動いている間、効果は効果ごとに決めた間隔（初期 1 秒）で働く
- 紋様の修飾は、消費量に倍率をかける
- Essentia 不足: 持続型は停止し、起動型は発動しない。不足そのものでは Flux は出ない
- 働いた分の Flux: 陣は働くたびに少しずつ Flux を出す（下の「効果が及んだしるし」）。使えば使うほど浄化・封じ込めが要る

- 天候: Aqua = 雨、Ignis = 晴れ、Tempestas = 雷雨を「強度 × 5 分」続ける

### 4.6 陣のランクと子の陣（M2-33・M2-34・M5）

- 陣のランクは Core の素材で決まる。今の Core（金）がランク 1

| ランク | Core の素材 | リング | スロット | 時期 |
|---|---|---|---|---|
| 1 | 金 | 3 重（11×11） | 3 | M1（今の Core） |
| 2 | 魔鉄 | 4 重（15×15） | 3 | M2 |
| 3 | 天銀 | 5 重（19×19） | 4 | M2 |
| 4 | 道の素材（暁金か宵鋼。§17.9） | 6 重（23×23） | 5 | M5 |
| 5 | Nihil | 7 重（27×27） | 5 | M5（儀式のあと） |

- ランクが上がると、次のようになる
  - 描けるリングが増え、そのぶん節点（修飾を描ける所）も増える
  - 範囲と強度が上がる
  - 上位の効果が開く: 第 3 層のアスペクトを使う組み合わせと道の効果は、組み合わせのファイルに書いたランク以上の Core でないと動かない（未定義の組み合わせと同じ扱いにはせず、ルーペで「この Core では動かない」と出す）
  - スロットが増える。増えたスロットは、組み合わせによって効果の鍵にもパラメータにも使う（組み合わせのファイルで決める）
- 見た目: Core の回る円は、ランクが高いほど大きくなる。動いている陣の上には、描いた線をなぞる光の紋が薄く浮かび、ランクが高いほど大きく鮮やかになる。起動型は発動した瞬間だけ
- 子の陣: 高いランクの陣の外側のリングの節点に、修飾の代わりに低いランクの Core を置くと、その Core の効果（子の陣）が親の範囲と強度で動く
  - 1 つの陣で 2 つの効果を重ねるのは、スロットではなくこの仕組みで行う
  - 詳しくは下の「子の陣（M2-34）」
- ランク 2・3（M2-33）
  - 作り方: 作業台で、中央に 1 つ下のランクの Core、上下左右に魔鉄のインゴット（ランク 3 は天銀のインゴット）、四隅に石レンガ。素材が章で開くので、進みもそれに沿う。ブロックは別（`thaumory:arcane_iron_circle_core`・`thaumory:aether_silver_circle_core`）で、振る舞いは同じ
  - 範囲: リングの半径は 4 重 = 24、5 重 = 32（`ring_radius` に足す）。強度: ランクが 1 つ上がるごとに強度の倍率に +0.25（`rank_strength`。修飾と同じ足し算）
  - 組み合わせのファイルの `rank`（省略すると 1）: それより低いランクの Core では動かない。未定義の組み合わせとは扱わず、Flux も記録も出さない。杖とルーペで「この Core では動かない」と出す
  - スロット 4: ランク 3 から挿せる。組み合わせのファイルの `slot4`（`slot3` と同じ書き方。省略すると空だけ許す）で決める。今ある効果はどれも空だけ
  - Core の回る円は、ランク 2 で 1.2 倍、ランク 3 で 1.4 倍の大きさ。アイテムのテクスチャは仮
- 光る紋（M2-33）: 動いている陣の上に、成立したリングの円と節点の位置をなぞる淡い光の線が、少し浮いてゆっくり浮き沈みする。色はスロット 1 のアスペクト。輪のグローと同じく、ぼかした光で描く。起動型は発動した瞬間だけ（1 秒ほどで消える）
- 子の陣（M2-34）
  - 置き場所: 親の陣の成立した一番外のリングの節点（東西南北）。修飾の紋様の代わりに、親より低いランクの Core を親と同じ面に置く。その Core はリングの一部として数え、そのマスの修飾は無い
    - 節点以外のマスの Core はリングの一部として数えない（リングは欠ける）
  - 抱えられる数: 親のランク − 1（ランク 1 は抱えられない。ランク 2 で 1、ランク 3 で 2、ランク 4・5 で 3・4）。数を超えた分と、親より低いランクではない Core は、リングの一部としては数えるが子の陣としては働かない。どれが子になるかは北・東・南・西の順
  - 子の Core は自分の周りのチョークを読まない。親の陣の一部として動き、子が子を抱えることはない
  - 起動: 子の Core を杖で右クリックして、それぞれ起動・停止・発動する（今までの Core と同じ操作）。親の陣のリングが成り立っていれば働き、親が動いている必要はない（Rune の無い親を枠として使ってもよい）。親のリングが崩れる・子が節点から外れると、子の陣は止まる
  - 範囲と強度: 範囲は親の Core を中心に、親の成立したリングの数で決まる半径。強度・範囲・消費の倍率は親のもの（親の修飾と親のランクの強度の加算）を使う
    - 効果の場所: 範囲の中心は親の Core。Essentia の置き場所・落ちた品の出る場所・Flux の出るチャンク・陣の向き（採掘の奥など）は子の Core のもの。API の `CircleContext.centre()`（範囲の中心。既定は `core()`）で効果に渡す
  - Essentia: 子の Core に入れた、子の Rune のアスペクトを払う（配管も子の Core へつなぐ）
  - 不安定度: 子の陣は親の不安定度で判定する。親の不安定度は、抱えた子の陣 1 つにつき +1（`circle.json` の `child_instability`）
  - ランクの条件: 組み合わせのファイルの `rank` は子の Core のランクで判定する（上位の効果には、子でも上位の Core が要る）
  - 光る紋: 子の陣が動いている間（起動型は発動した瞬間）、親のリングのうち子が座っている一番外のリングの円と、その節点の点だけが、子のスロット 1 のアスペクトの色で光る。親が動いていなくても出る。親の光る紋と重なるときは少し上に浮かべる
  - ルーペ: 親の Core では抱えた子の陣の数と上限を出す。子の Core では「子の陣」と親のリングの数・不安定度を出す。働かない Core（数を超えた・ランクが足りない）には、その理由を出す
- 封印の間の祭壇は、作れない特別な Core（§17.8）。自分の Core は要らない

## 5. Flux（汚染）

- チャンクごとの数値（Fabric Data Attachment）。チャンクを越えて拡散しない
- 量は小数で持つ。1 未満になったら 0 とみなし、チャンクからデータを消す。段階の判定は整数部で行う
- 自然減衰する（初期値: ゲーム時刻の 72000 tick ごとに 10%、途中も連続的に減る）。浄化の陣で速く減らせる
  - 定期処理では減らさない。「量」と「最後に書き込んだゲーム時刻」を保存し、読むときに経過時間から計算する。読み込まれていないチャンクも同じように減る
- 減衰率と段階の閾値は `data/thaumory/thaumory/flux.json` に書く。上位の datapack が同じパスのファイルで丸ごと置き換える。ファイルが無い・不正な場合は初期値を使う
  - 形式: `{"decay": {"fraction": 0.1, "interval": 72000}, "stages": {"stagnation": 50, "erosion": 150, "manifestation": 300, "overload": 500}}`
  - 段階の種類と影響はコードで固定する
- 発生源: 陣が働いた分（§4.5）、未定義の陣の組み合わせ、不安定度の超過、Crucible での打ち消し・容量超過、瓶内での打ち消し、パイプの破壊、注入の失敗、Flux の結晶が割れる・溶ける（§17.5）、ポーション調合での Flux の渦への接触

| 段階 | 量 | 影響 |
|---|---|---|
| 淀み | 50〜 | 紫色のパーティクル。本に警告が出る（本を開いたとき、今いるチャンクが淀み以上なら上部に段階と警告を帯で出す） |
| 侵食 | 150〜 | 周囲のブロックが汚染されたブロックに変質する。作物が育たない |
| 顕現 | 300〜 | Flux から生まれた敵対mobが湧く。陣の不安定度が上昇する |
| 暴走 | 500〜 | 範囲内の陣が確率で暴発する |

- 汚染されたブロックは、浄化の陣の範囲内で元に戻る
- 数値はすべて JSON で調整できるようにする

### 5.1 段階の影響の詳細

- 影響はプレイヤーの近く（各プレイヤーから半径 3 チャンク以内の読み込まれたチャンク）でだけ、一定の間隔で処理する。量は処理のたびに読み直す（減衰を反映する）
- 淀み以上: 2 秒ごとに、チャンクの地表の上に紫のパーティクル（`minecraft:witch`）を出す。数は段階が上がるほど多い（淀み 2・侵食 4・顕現 6・暴走 10）
- 侵食以上
  - 10 秒ごとに、チャンクの地表のランダムなマスを数か所（侵食 1・顕現 2・暴走 3）選び、変質できるブロックなら汚染ブロックに変える
  - 作物（ブロックタグ `minecraft:crops`）はランダムティックで育たない。成長の陣も育てない
- 顕現以上
  - 30 秒ごとに確率（初期 50%）で、チャンクの地表の上に「虚空の残滓」を 1 体湧かせる。1 チャンクあたり 3 体まで
  - そのチャンクにある陣の不安定度が +3 される（判定と表示の両方）
- 暴走: そのチャンクの陣は、Essentia を払うたびに確率（初期 25%）で暴発する
  - 暴発: 効果は働かず、払った Essentia は失われ、未定義の組み合わせと同じ量の Flux が出る。持続型は止まる
  - 汚染爆発: Core を中心に、ブロックを壊さない爆発（音と粒子、半径 4 の生き物に 4 ダメージとノックバック）が起き、半径 4 の変質できるブロックがすべて汚染ブロックになる。陣そのものは残る
  - 杖で発動・起動したときに暴発すると、アクションバーに暴発を知らせる（震え（強））
- 数値は `flux.json` の `effects` に書く。書かれていない値は初期値
  - 形式: `{"effects": {"particles": [2, 4, 6, 10], "pollution_interval": 200, "pollution_attempts": [1, 2, 3], "polluted_block_flux": 0.02, "spawn_interval": 600, "spawn_chance": 0.5, "spawn_cap": 3, "manifestation_instability": 3, "misfire_chance": 0.25, "explosion_radius": 4, "explosion_damage": 4}}`（配列は段階の順。`particles` は淀みから、`pollution_attempts` は侵食から）

### 5.2 汚染ブロック

- 2 種類: 汚染された土（草・土系から）、汚染された石（石・丸石・深層岩から）。どちらも普通に掘れて、それ自身を落とす
- 変質の対応は `data/<namespace>/thaumory/pollution/*.json` に 1 ファイル 1 種類で書く。上位の datapack の同じパスのファイルが丸ごと置き換える
  - 形式: `{"polluted": "thaumory:polluted_soil", "from": ["#minecraft:dirt", "#minecraft:grass_blocks", "minecraft:farmland"], "restore": "minecraft:dirt"}`（`from` はブロックかブロックタグ）
- 浄化の陣: 1 秒ごとに、範囲内の汚染ブロックを最大「2 × 強度（切り上げ）」個、`restore` のブロックに戻す（`restore_per_second`）
- 汚染ブロックは Flux を出す: 汚染の間隔（初期 10 秒）ごとに、プレイヤーの近くのチャンクの Flux が「そのチャンクの汚染ブロックの数 × 0.02」増える（`polluted_block_flux`）。ただし侵食の閾値の手前までしか増やさない（汚染ブロックだけでは侵食以上に進まない）。1 つなら自然減衰と釣り合って淀みに留まり、浄化しないと淀みが消えない

### 5.3 虚空の残滓（Void Remnant）

- Flux から生まれた敵対 mob。ヴェックスほどの大きさで宙に浮き、飛び回ってプレイヤーを追い、近接攻撃する（体力 8・攻撃 2）。壁は抜けない
- 見た目: ヴェックスの形で、体の中にエンドポータルと同じ星空が流れる
- 倒されると、そのチャンクの Flux が 10 減る。何も落とさない
- 普通の敵と同じく、プレイヤーから離れると消える

## 6. リサーチ

### 6.1 知識の可視性

- アイテムのアスペクトは、最初は見えない。魔術のルーペ（§7.2）でスキャンすると本に記録され、以降はツールチップに表示される。スキャンしていないアイテムにはアスペクトの行を出さない
- アスペクトそのものも未知から始まる。初見は名前の代わりに読めない紋字が表示され（量と、アスペクトの色は見える）、そのアスペクトを含むアイテムを一定数スキャンすると名前が判明する
  - 紋字: 自前のフォントの読めない文字（3〜4 文字）を、アスペクトの色でシェーダーにより揺らめかせて描く（§7.6）。並びはアスペクトの ID から決まり、同じアスペクトならいつも同じ（未判明のまま見分けられる。アドオンのアスペクトにも自動で付く）。紋字はアスペクトの名前を暗号にしたものではない（読み解いても名前は分からない）
  - 数は異なるアイテムの種類で数える（初期値 3）。`data/thaumory/thaumory/scanning.json` の `{"reveal_after": 3}` で変えられ、上位の datapack が丸ごと置き換える
  - アスペクトのないアイテムもスキャン済みとして記録する
- 魔法陣: 成功した組み合わせも、失敗した組み合わせも本に記録される
  - 成功は、陣を起動した人に記録する（持続型の起動・起動型の発動が Essentia 不足でなく行われたとき）。失敗は、未定義の組み合わせを試した人に記録する（§4.1）
- ポーションマップ: 最初は霧に覆われ、マーカーが通った場所だけが見えるようになる

### 6.2 ヒントと進行ツリー

- スキャンや陣の成功が一定数に達すると、本に断片的な記述が現れる（例: 「Arcanum は、Aer と結びつくとき、空間を歪める」）
- 進行ツリー: 節目（最初の Crucible、アスペクトを5つ判明させる、初めて陣を発動する、など）を本の章として表示する。章をクリアすると次の章とレシピが開放される
- ヒントの出現条件は進行ツリーの項目として JSON で定義する

#### 章

- `data/<namespace>/thaumory/research/chapter/*.json` に 1 ファイル 1 章。上位の datapack の同じパスのファイルが丸ごと置き換える
  - 形式: `{"icon": "minecraft:cauldron", "category": "thaumory:alchemy", "x": 1, "y": 0, "requires": ["thaumory:beginning"], "conditions": [{"type": "thaumory:scanned", "item": "thaumory:crucible"}], "unlocks": ["thaumory:blank_rune"]}`
  - `category`: 分野の ID。省略すると `thaumory:basics`。`x`・`y`: 分野の樹形図の格子の座標（右と下が正）。省略すると、同じ分野の最初の `requires` の章の右隣（埋まっていれば下へずらす）、`requires` が無ければ (0, 0)
- 分野: `data/<namespace>/thaumory/research/category/*.json` に 1 ファイル 1 分野。形式: `{"icon": "thaumory:arcane_codex", "order": 0, "background": "minecraft:block/dark_oak_planks"}`（`order` はしおりの並び。同じなら ID 順。`background` は樹形図に敷くテクスチャ（`textures/<path>.png`、16×16 を並べる）。省略すると石）。名前は翻訳キー `category.<namespace>.<path>`
  - 初期の背景: 基礎 = 濃いオークの板材、錬金術 = 磨かれたブラックストーンのレンガ、陣 = エンドストーン、金属と装備 = 鉄ブロック
  - 初期の分野: 基礎（はじまり・アスペクト・探究・暴きのモノクル）、錬金術（るつぼ・ルーン）、陣（魔法陣・Flux）、金属と装備（魔術の金属・天の銀）
  - タイトルと本文は翻訳キー `chapter.<namespace>.<path>` と `chapter.<namespace>.<path>.text`
- 状態: `requires` の章がすべて完了すると「開いた」章になり、本に本文と条件（それぞれ満たしたかどうか）と開放するレシピが出る。開いていない章の出し方は §7.3。`conditions` をすべて満たすと完了する（条件が無ければ開いた時点で完了）
- 条件の種類（コードで固定。すべて知識から数える）
  - `thaumory:scanned`: `item`（そのアイテム）、`tag`（そのタグのどれか）、`count`（スキャンした種類の数）のどれか 1 つ
  - `thaumory:aspects`: `count`（判明したアスペクトの数）または `aspects`（すべて判明）
  - `thaumory:circles`: `outcome`（`success` か `failure`）の組み合わせの数が `count` 以上（省略すると 1）。`effect` を書くと、その効果の組み合わせだけを数える
- 判定: 知識が変わったとき、ログインしたとき、datapack を読み直したとき。完了は連鎖する（完了で開いた章の条件がすでに満たされていれば、続けて完了する）
- 完了すると、チャットに章の名前（光の筋）を知らせる
- 錬金術レシピの開放: 章の `unlocks` に書いたレシピは、その章を完了した人だけが使える。どの章にも書かれていないレシピは最初から使える
  - Crucible は、触媒を投げ入れた人の知識で判定する。投げた人が分からないとき（ホッパーなど）は、最初から使えるレシピだけ。使えないレシピの触媒は普通に溶ける
  - アスペクトの推定には、開放に関係なくすべてのレシピを使う

#### ヒント

- `data/<namespace>/thaumory/research/hint/*.json` に 1 ファイル 1 つ。形式: `{"conditions": [...]}`（章と同じ条件）。文は翻訳キー `hint.<namespace>.<path>`
- 条件を満たすと本のヒントに加わり、チャットに「本に新しい記述が現れた」と出る

#### 初期の章とヒント

| 章 | 前の章 | 条件 | 開放 |
|---|---|---|---|
| はじまり | なし | なし | |
| アスペクト | はじまり | アスペクトを 1 つ判明 | |
| るつぼ | はじまり | Crucible をスキャン | |
| ルーン | アスペクト・るつぼ | アスペクトを 3 つ判明 | 空の Rune・基本のチョーク |
| 魔法陣 | ルーン | 陣の成功 1 | 修飾のチョーク 4 種・白紙の巻物 |
| Flux | 魔法陣 | 陣の失敗 1 | |
| 探究 | アスペクト | アスペクトを 12 判明 | |
| 魔術の金属 | 魔法陣 | 鉄インゴットをスキャン | Arcane Iron |
| 天の銀 | 魔術の金属 | Arcane Iron をスキャン・Aer と Lux を判明 | Aether Silver |
| 暴きのモノクル | アスペクト・るつぼ | Lux と Arcanum を判明 | 暴きのモノクル |

- ヒントは MVP の効果 8 種ごとに 1 つ。その組み合わせのスロット 1・2 のアスペクトを両方判明させると現れる（例: Arcanum と Aer →「Arcanum は、Aer と結びつくとき、空間を歪める」）

### 6.3 マルチプレイ

- 知識はプレイヤーごと（Fabric Data Attachment）。死んでも消えない。変化するたびに、そのプレイヤーのクライアントへ全体を送る
- 保存する知識（すべて ID で持つ。無くなった Mod の ID も消さない）
  - スキャン済み: レジストリごとの ID の集合（M1 ではアイテムのみ。ブロックはそのアイテムとして記録する。mob などは種類を足して対応する）
  - 判明したアスペクト: 一度判明したら、アイテムの値が変わっても未判明に戻らない
  - 陣の試行: スロット1・2（順不同）とスロット3の組み合わせごとの成功・失敗。一度成功した組み合わせは成功のまま
  - 完了した章と、出現したヒントの ID。章の条件は他の記録から数えるので、途中の進捗は持たない
- 本のページを書き写して、知識を1つ含んだアイテム「知識の写し」として他のプレイヤーに渡せる
  - 書き写せる知識: 判明したアスペクト 1 つ、または成功した陣の組み合わせ 1 つ（スロット 3 まで含めた、試したとおりの組み合わせ）。スキャン済み・失敗した陣・章・ヒントは書き写せない
  - 作り方: 本のアスペクトのタブか陣のタブで項目を選び、「書き写す」を押す。インベントリの紙 1 枚とイカスミ 1 つを使う（クリエイティブでは使わない）。足りなければアクションバーに出す。自分が知らない知識は書き写せない（サーバーが知識で確かめる）
  - 名前は中身で変わる（アスペクトの写し / 陣の写し）。ツールチップには中身を持っている人の知識で出す（未判明のアスペクトは紋字。陣は効果名を出さない）。スタックしない
  - 使う: 右クリックで中身を習得し、写しは 1 つ減る。アスペクトは判明に、陣はその組み合わせの成功になる。すでに知っていれば減らさず、アクションバーに「もう知っている」と出す
  - 習得した知識は自分で見つけたものと区別しない（章の条件にも数え、ヒントも現れる）。習得するとチャットに知らせる

## 7. 道具

### 7.1 杖（作業用）

- 陣の起動・停止。陣の状態を見るのはルーペ（§7.2）
  - レシピ: 下の「部品（M2-12）」。金の金具 2 と木の芯（棒）で、今までの杖と同じもの
  - Core を右クリック: 持続型なら起動と停止を切り替え、起動型なら 1 回発動する。結果（起動した・止めた・リングが成立していない・組み合わせが働かない・Essentia が足りない）をアクションバーに出す
  - スニーク + 右クリックで、Core に組み込んだ台座を外す（§10.1）
  - スタックしない。耐久値は無い
- 焦点を付けると呪文を撃てる（§17.7。M2-29）。焦点が無ければ呪文は撃たない
- 部品（M2-12）: 杖は金具と芯の組み合わせ。作業台で金具 2 + 芯 1
  - 金具: 焦点のために内蔵できる Essentia の量を決める。金・魔鉄・天銀、M5 で道の素材（暁金か宵鋼。§17.9）
  - 芯: 焦点の威力と、掘削の焦点の採掘段階を決める。木の棒・結晶などから、M5 で道の素材
  - 組み替えても、内蔵の Essentia と付けた焦点は残る。耐久値が無いのは今までどおり
  - 部品のアイテム
    - 金の金具: 作業台で金塊 2（不定形）。魔鉄の金具・天銀の金具: それぞれのインゴット 1 + 金塊 1（不定形）
    - 木の芯: 棒そのもの。結晶の芯: 錬金術で、棒を触媒に Arcanum 8 + Lux 4。章「魔術の金属」で開く
  - 組む: 作業台で、同じ金具 2 と芯 1 を斜めに並べる（芯が真ん中）。どの金具と芯の組み合わせも 1 つの特別なレシピで扱う（アドオンの部品でも組める）
  - 組み替え: 作業台で、杖 + 同じ金具 2、または杖 + 芯 1（不定形）。部品を差し替えた杖になり、外した部品は置いたマスに残る。今と同じ部品では組み替えない
  - 性能: `data/<ns>/thaumory/wand_part/*.json` に 1 ファイル 1 部品で書き、`/reload` で読み直す。金具は `cap` に内蔵量（アスペクトごと）、芯は `core` に焦点の威力の倍率と採掘段階（掘れないブロックのタグ。道具の素材と同じ書き方）
    - 形式: `{"item": "thaumory:gold_wand_cap", "cap": {"essentia": 16}}`、`{"item": "minecraft:stick", "core": {"power": 1.0, "incorrect_for": "minecraft:incorrect_for_stone_tool"}}`
    - 初期値: 金具は 金 16・魔鉄 32・天銀 64。芯は 木 = 威力 1.0・石級、結晶 = 威力 1.25・鉄級。M5 の道の芯でダイヤ級以上
  - 杖は金具と芯のアイテム ID をコンポーネントに持つ。持たない杖（今までの杖）は「金の金具 + 木の芯」とみなす
  - ツールチップに金具と芯の名前と性能（内蔵量・威力・採掘段階）を出す。性能はサーバーが送る
  - 見た目: 杖の絵は芯の層（軸）と金具の層（先端と根元）を重ねたもので、それぞれ部品で絵が変わる。部品の記録が無い杖・アドオンの部品は金と木の絵
  - 内蔵した Essentia の払い方・補充・焦点の付け外しは §17.7（M2-29）

### 7.2 魔術のルーペ（Arcane Loupe）

- 見る道具。スキャンと Flux の計測を受け持つ。利き手・オフハンドのどちらに持っていても表示は出る
- レシピ: 作業台で、結晶のかけら（§17.3）+ 金塊 2 + 棒
- スキャン: 利き手に持って右クリックすると即座にスキャンする。狙いは 地面のアイテム > ブロック（そのアイテムとして）> オフハンドのアイテム の順。ブロックを右クリックしても GUI は開かない
- Flux の計測: ルーペを持っている間、画面の右上に今いるチャンクの Flux の量（整数）と段階を出す。段階は色を変える。サーバーが 1 秒ごとに送る
  - スニーク + 右クリックは今は使わない（後の操作のために空けておく）
- 見ているブロック: 照準の右に、ブロックの名前と、そのアイテムをスキャン済みならアスペクト（未スキャンなら「未スキャン」）を出す。アイテムの無いブロックは名前だけ。Crucible・瓶・Core は以下のとおり中身を出す
- Crucible を見る: ルーペを持って Crucible を見ると、中身・水・沸騰の状態が画面に出る
- 調合モードの Crucible を見ると、ポーションのマップも出る（M3、§9）
- パイプを見る（M2-14）: そのネットワークの運び中の Essentia（未判明のアスペクトは紋字）・パイプの本数・つながった容器の数が画面に出る。フィルタ付きパイプならフィルタのアスペクト、バルブなら開いているか閉じているかも出す
  - ネットワークはサーバーにしか無いので、ルーペを持ってパイプを見ている間だけ、サーバーが 0.25 秒ごとに送る。閉じたバルブは、そのバルブに残っている分を出す
- Core を見る（陣の診断）: 挿した Rune（未判明のアスペクトは紋字）・成立したリングの数・節点の修飾・無視された修飾の数・不安定度と閾値・動作中かどうか・中の Essentia が画面に出る。閾値を超えていれば警告を出す
  - 効果の名前と消費量は、見ている人が一度起動に成功した組み合わせのときだけ出す。試していなければ「未知の陣」、失敗と記録されていれば「失敗した組み合わせ」と出す（試す前に正解が分からないように）
  - 子の陣（§4.6）: 親の Core では抱えた子の陣の数と上限、子の Core では「子の陣」と親のリングの数・不安定度、働かない Core にはその理由も出す
  - 判定はサーバーが一定の間隔で行うので、描き替えてから表示が変わるまで少し（最大で判定の間隔）かかる

### 7.3 魔術の書（Arcane Codex）

- 知識を読む本。レシピ: 作業台で、本 + 魔術のルーペ（不定形。ルーペは消費する）
- 右クリックで開く。見開きの本の形（革の表紙の上に羊皮紙の 2 ページ）。タブは本の上の縁から出たしおり
  - 章: 分野ごとの樹形図（進捗の画面のように）。見開き全体に描き、ドラッグで動かす。動かした位置はゲームを起動している間だけ分野ごとに覚える
    - 背景: 図の場所はページの代わりに分野の背景のタイル（`background`）で埋め、図と一緒に動く。本の折り目は描かない
    - 分野の切り替え: 見開きの左の縁から出たしおり（分野のアイコン）。開いた章か「？」の章が 1 つもない分野は出さない
    - ノード: 章のアイコンを枠に入れて、章の座標（§6.2）に置く。完了は金の枠、開いた章は普通の枠。カーソルを合わせると章の名前
    - 線: 同じ分野の `requires` の章から線を引く。前の章が別の分野にあるときは引かない
    - まだ開いていない章は、`requires` の章のうち 1 つでも完了していれば、名前のない薄い「？」の印で出す（カーソルを合わせると「未知の章」）。それ以外は出さない
    - ノードをクリックすると、見開きがその章のページになる（本文・条件・開放するレシピ。長ければページ送り）。「戻る」で図に戻る
  - ほかのタブは、中身を左のページから右のページへ続けて並べる
  - アスペクト: 登録されたすべてのアスペクトを、大きいアイコンの格子で並べる（未判明は共通の「未知」のアイコン）。カーソルを合わせると名前と構成が出る（未判明は紋字だけ）
  - スキャン済み: アイテムのアイコンの並び。カーソルを合わせると名前とアスペクト
  - 陣: 試した組み合わせと成功・失敗
  - アスペクトのタブで判明したアスペクトを、陣のタブで成功した組み合わせをクリックすると選ばれ、下の縁に「書き写す」が出る（§6.3）
  - ヒント: 出現したヒント（中身は M1-10）
- 中身はクライアントにある知識をそのまま表示する。サーバーには問い合わせない

### 7.4 チョーク

- Crucible の錬金術で作る。耐久値あり（1マスごとに1消費、64）
- 基本の線用と、修飾の紋様ごと（増幅・延長・節約・安定）に分ける。色で区別する（基本 = 白、増幅 = 赤、延長 = 水色、節約 = 緑、安定 = 黄）。修飾のチョークは基本のチョークを触媒にして作る
- 描いた線はブロックの上面に乗る薄い装飾ブロックになる。チョークで右クリックすると消せる。つながりは自動判定する
  - 描く: チョークでブロックの面を右クリックすると、その面に描く（上面なら床、側面なら壁、下面なら天井）。描く面がしっかりしているときだけ描ける。耐久値を 1 消費する（クリエイティブでは消費しない）
  - 描いてある紋様を右クリックすると、同じ種類のチョークなら消し（耐久値は消費しない）、違う種類なら描き替える（1 消費）
  - つながり: 同じ面の上で上下左右に隣り合う紋様とは、種類を問わず線でつながって見える。斜めに隣り合う紋様とはつながらない（円のリングの段差は点で切れて見える。斜めの線は、隣のリングどうしがつながってしまうのでやめた。M2-35）。面の違う紋様とはつながらない
  - 見た目: 基本の線は白。修飾は中央にその色の印を描き、線も同じ色にする
  - 紋様はアイテムを落とさない。描いた面のブロックが無くなる、水が流れ込む、ピストンで押されると消える

### 7.5 クリエイティブタブ

- Thaumory のアイテムはすべて専用のタブ「Thaumory」にまとめる。バニラのタブには入れない
- Rune はアスペクトごとに 1 つずつ並べる。瓶は空の瓶に続けて、アスペクトごとに Essentia が満タン（容量の初期値 64）の瓶を並べる（ラベルなし）

### 7.6 文字の演出

- 演出は自前のフォント ID（`thaumory:` 以下）で表し、そのフォントの文字を自前のシェーダーで描く。文字の Style に載るので、ツールチップ・HUD・本・チャットのどこでも同じに動き、datapack やアドオンのテキスト JSON からも使える
- 演出の種類: 揺らめき（紋字）、脈動、にじみ（明滅）、波、震え（弱・強）、光の筋
- 使う場所:

| 場所 | 演出 |
|---|---|
| 未判明のアスペクト | 紋字 + 揺らめき（アスペクトの色） |
| 判明したアスペクトの名前 | アスペクトごとの演出（§2.2） |
| Flux の段階（ルーペの HUD、本の警告） | 淀み = 脈動、侵食 = にじみ、顕現 = 波、暴走 = 震え（強） |
| 陣の失敗「陣が乱れ、Flux が漏れ出した」・ルーペの「不安定」の警告 | 震え（強） |
| ルーペの「失敗した組み合わせ」 | 震え（弱） |
| アスペクトが判明したときの名前・陣が初めて成功したときのメッセージ | 光の筋 |
| ルーペの「動作中」と効果名 | 脈動（Rune の色） |

## 8. 魔術工学

### 8.1 輸送の段階

1. 手動（瓶で運んで注ぐ）— M1
2. 配管 — M2
3. 無線 — M5

### 8.2 配管（M2）

- パイプ、瓶（ラベル付きはそのアスペクトのみ受け入れる）、フィルタ付きパイプ、バルブ（レッドストーン制御）、ポンプ（Crucible から吸い出す）
- 吸引力方式: 需要側が吸引力を持ち、一番強い場所へ流れる（Core > ラベル付きの瓶 > ラベルなしの瓶）
- 1 tick あたりの流量に上限がある（パイプのランクで変わる）
- ラベルなしの瓶で正反対のアスペクトが混ざると Flux。パイプを壊すと中身が Flux として漏れる
- ネットワーク（繋がっているパイプの集合）単位で計算し、変化したときにだけ再構築する
- Fabric Transfer API（`Storage<EssentiaVariant>`）で実装し、他Modと接続できるようにする
- Essentia の Storage（M2-1）
  - 口は Loader に依存しない `EssentiaContainer`（`thaumory-api`）。Fabric では `Storage<EssentiaVariant>` に包み、BlockApiLookup `thaumory:essentia`（面ごと）で公開する。NeoForge は M4 で同じ口を capability に包む
  - 量は Essentia 1 = 1。出し入れはトランザクションが確定したときに反映する
  - Crucible: どのアスペクトも取り出せる。入れるのは容量まで（溢れさせず、Flux も出さない）。入った後の打ち消しはいつもどおり（沸騰している間）
  - 瓶: ラベル付きはそのアスペクトだけ出し入れできる。ラベルなしはどれでも。どちらも容量まで。ラベルなしの瓶で正反対が混ざると、確定したときに打ち消し合い、減った分がそのチャンクの Flux になる
  - Core: 挿した Rune のアスペクトだけ、アスペクトごとに容量まで入る。取り出せない
  - どの面からでも同じ
- パイプとネットワーク（M2-2）
  - パイプ（基本）: 作業台で、横一列に 金塊・ガラス・金塊 を 3 段（ガラス 3 + 金塊 6）で 8 本。上のランクは M2-6 の素材ができてから足す
  - つながり: 6 方向の隣のパイプと、Essentia の Storage を持つブロック（Crucible は除く。ポンプだけがつながる）につながる。見た目は中心の細い管と、つながった方向への腕
  - ネットワーク: つながったパイプの集合。パイプを置く・壊す・隣のブロックが変わったときにだけ作り直す。一定の間隔（初期 0.5 秒）ごとに動く
  - 優先度: Core 3 > ラベル付きの瓶 2 > ラベルなしの瓶 1。他 Mod の Storage は 1。Essentia は優先度の低い容器から高い容器へだけ流れる（同じ優先度どうしでは流れない）
  - 運び中: ネットワークは運び中の Essentia を持つ（容量 = パイプの数 × 4）。1 回ごとに、まず運び中のものを受け手へ渡し（優先度の高い順、受け手 1 つにつき 1 回 4 まで）、次に受け手の空きに向けて、それより優先度の低い容器から運び中へ吸い出す（運び中の空きまで）。吸い出したものは次の回に届く
  - 運び中の Essentia はパイプに分けて保存する（ワールドを出入りしても消えない）
  - 壊したとき（M2-4）: 運び中をパイプの本数で分けたうち、そのパイプの分が、そのチャンクの Flux として漏れる。チャンクが読み込まれなくなるだけなら漏れない
- 中身の描画（M2-15）: 運び中の Essentia があるネットワークのパイプは、ガラスの中に液を描く
  - 色は運び中のアスペクトの色を量の割合で混ぜた色（瓶の液面と同じ）。横向きの管は、液の高さ = 運び中 ÷ 容量 を 4 段階に丸めたもの。縦向きの管は、空でなければ満たして描く
  - 色か段階が変わったときだけ、そのネットワークのパイプをクライアントへ送る。閉じたバルブは、残っている分で描く
- フィルタ付きパイプ・バルブ・ポンプ（M2-3）。どれもパイプの一種で、パイプどうしと同じようにつながり、ネットワークに加わる
  - フィルタ付きパイプ: アスペクトの Rune を持って右クリックすると、そのアスペクトのフィルタになる（Rune は減らない）。スニーク + 素手で外す。外れていれば普通のパイプと同じ。帯がアスペクトの色になる
    - フィルタ付きパイプに触れている容器とは、そのアスペクトだけを出し入れする。同じ容器に普通のパイプや別のフィルタも触れていれば、それらが通すものを合わせたものが通る
  - バルブ: レッドストーン信号が入ると閉じ、閉じている間はネットワークの一部でなくなる（そこでネットワークが切れる）。閉じたバルブの分の運び中はバルブに残り、開くと戻る。漏れない
  - ポンプ: 隣の Crucible を、優先度 0 の出し手としてネットワークに加える（吸い出すだけで、Crucible へは入れない）。電源は要らない
  - レシピ（作業台・不定形）: フィルタ付きパイプ = パイプ + 金インゴット、バルブ = パイプ + レバー、ポンプ = パイプ + ピストン
  - 数値は `data/thaumory/thaumory/pipe.json`: `{"interval": 10, "rate": 4, "buffer_per_pipe": 4}`。上位の datapack が丸ごと置き換える

### 8.3 無線（M5）

- 送り手と受け手の台を杖でリンクする
- 転送のたびに距離に比例して損失する（例: 100ブロックごとに5%）。次元はまたげない
- 詳細は M5 の実装時に決める

## 9. ポーション調合（M3）

- Crucible の調合モードで行う。GUI は開かず、魔術のルーペを持って Crucible を見ると画面の端にマップの HUD が表示される。ルーペはオフハンドに持っていてもよい（杖でかき混ぜながら見られるように）
- マップ: 六角形。中心が原点（水）。Primal の6方向に関係の深い効果、複合アスペクトの方向に高度な効果を配置する。Flux の渦（障害物）がある
- 進路: 材料のアスペクトを、量が多いものから順に線分でつないだ折れ線
  - 複合アスペクトは、構成する Primal の線分2本に展開する（和の1本にはしない）。1つ飛ばしの複合アスペクトの到達点は Primal と一致するが、経路が異なる

| 操作 | 方法 | 効果 |
|---|---|---|
| 材料を入れる | アイテムを投げ入れる | 進路が描かれる |
| かき混ぜる | 杖（またはヘラ）で右クリックし続ける | マーカーが進路に沿って進む |
| 水を足す | 水入りの瓶を使う | マーカーが原点の方向へ戻る |
| 回転させる | Ordo の塩 / Chaos の塩 | マーカーの周りで進路が回転する |
| 確定させる | 熱源を強める（ふいごなど） | 近くの効果でポーションが完成する |

- 効果の中心への近さで、レベルと持続時間が変わる。最大3つの効果を重ねられる

## 10. 注入と装備（M2）

### 10.1 注入の陣

- Core の上に台座を置き、そこにアイテムを載せて杖で起動すると、陣の効果をアイテムに焼き付ける（1回限り、大量の Essentia を消費する）
- 陣の組み合わせは、設置効果の陣と同じものを使う（例: 治癒 → 防具に自然回復、テレポート → 右クリックでチャンネルの陣へ帰還）
- 紋様の修飾が反映される（増幅 = 効果のレベル、安定 = 失敗の確率を下げる）
- 失敗すると Essentia を失い、Flux が出る。アイテムは壊れない
- 効果の消費: パッシブは無償、アクティブは装備に内蔵した Essentia を消費する。補充は瓶から注ぐか、充填用の陣の上に置く
- 台座（M2-5）: Core に組み込む祭壇。台座のアイテムを持って Core を右クリックすると、Core のマスに台座が立つ（アイテムは 1 つ使う）。台座の付いた Core の見た目は、地面から 3/4 マスの細身の祭壇（金の帯の足・石レンガの柱・金の縁の天板）で、柱のまわりに紫に光る紋の輪が浮かんで回る。レシピ: 作業台で、石レンガのハーフブロック 3（上段）+ 金インゴット 1（中央）
  - 載せる: スタックしないアイテムか容量のあるアイテム（§10.2。白紙の巻物など）を持って台座付きの Core を右クリックすると、1 つ天板に載る（天板の上で浮いて回る）。Thaumory の道具（杖・瓶・チョーク・ルーペ・モノクル・魔術の書・Rune・台座）は載らず、いつもどおりに働く（アイテムタグ `thaumory:pedestal_ignored`）
  - 取る: 素手で右クリック。スニーク + 素手は今までどおり Rune を抜く
  - 外す: 杖でスニーク + 右クリックすると台座が外れて手元に戻る（載せていたアイテムも戻る）
  - Core を壊すと、台座と載せていたアイテムも落ちる
- 注入の手順: 台座にアイテムが載っているときに杖で Core を右クリックすると、設置効果の代わりに注入する（持続型・起動型を問わない。動いている持続型の陣でも止めない）
  - リングが成立していない・Rune が 2 つ未満なら何もしない。未定義の組み合わせなら陣の不発と同じ（§4.1）
  - 注入できるのは容量のあるアイテムだけ（§10.2）。容量が無ければ何も消費せず、アクションバーに「この品は陣の効果を受け入れない」と出す
  - 容量が足りなければ何も消費せず、アクションバーに使用量と必要な量を出す（§10.2）
  - 消費: スロット 1・2 のアスペクトを各 `runes`（初期 32）、スロット 3 のアスペクトを `parameter`（初期 4）。どちらも消費の倍率をかけて四捨五入（最低 1）。組み合わせのファイルの `"infusion_cost": {"runes": 32, "parameter": 4}` で変えられる。足りなければ何も消費せず、アクションバーに出す
  - 失敗: 確率 = 基本（初期 10%）+ 不安定度の超過 × 20%（最大 100%）。失敗すると消費した Essentia は失われ、その半分（切り上げ）が Core のチャンクの Flux になる。アイテムはそのまま
  - 成功: アイテムに「効果の ID・レベル・スロット 3 のアスペクト・容量のコスト」を焼き付ける。同じ効果がすでにあれば置き換え、違う効果なら足す。杖で起動したときと同じく、その組み合わせを成功として記録する
  - レベル = 1 + (強度 − 1) ÷ 0.5 を切り捨て（最低 1、最高 5）。増幅 1 つで II、2 つで III
  - 数値は `circle.json` の `"infusion": {"base_failure": 0.1, "failure_per_point": 0.2, "flux_ratio": 0.5, "max_level": 5}`
  - 結果（注入した・失敗した）はアクションバーに出す。焼き付けた効果はツールチップに「効果の名前 + レベル」で出す。効果がアイテムで働くのは M2-8

### 10.2 素材と容量

| ランク | 素材（仮名） | 作り方 | 容量 | 時期 |
|---|---|---|---|---|
| 1 | Arcane Iron | 鉄 + Arcanum（錬金術） | 3 | M2 |
| 2 | Aether Silver | ランク1 + Aer・Lux を大量に（錬金術） | 5 | M2 |
| 3 | 未定 | 専用の注入装置のみ | 8+ | M5 |

- 効果ごとに容量のコストがある（弱い効果は 1、テレポートなどは 3）
- 素材（M2-6）: Arcane Iron のインゴット・Aether Silver のインゴット。錬金術で作る。どちらも章で開放する（§6.2 の「魔術の金属」「天の銀」）
  - Arcane Iron: 鉄インゴット + Arcanum 8
  - Aether Silver: Arcane Iron のインゴット + Aer 16・Lux 16
- 装備一式: 素材ごとに 剣・ツルハシ・斧・シャベル・クワ・ヘルメット・チェストプレート・レギンス・ブーツ（2 素材で 18 種）。作業台でバニラと同じ形（柄は棒）。修理は同じ素材のインゴット（金床）
- 性能: 素の性能は控えめにし、価値は注入の容量で出す（バニラの鉄・ダイヤを置き換えない）

| | Arcane Iron | Aether Silver |
|---|---|---|
| 採掘の段階 | 鉄と同じ | ダイヤと同じ |
| 道具の耐久 | 350（鉄 250） | 1200（ダイヤ 1561） |
| 採掘速度・攻撃力 | 鉄と同じ（6・+2） | ダイヤと同じ（8・+3） |
| 防具の防御・強靭 | 鉄と同じ（2・5・6・2、強靭 0） | ダイヤと同じ（3・6・8・3、強靭 2） |
| 防具の耐久の倍率 | 21（鉄 15） | 26（ダイヤ 33） |
| エンチャント適性 | 18 | 22 |

- 剣・斧などの攻撃速度・攻撃力の基礎値は、Arcane Iron は鉄、Aether Silver はダイヤの同じ道具に合わせる
- 容量（M2-7）: `data/<namespace>/thaumory/infusion_capacity/*.json` に書く。形式: `{"values": [{"target": "#thaumory:arcane_iron_equipment", "capacity": 3}]}`（`target` の先頭の `#` はアイテムタグ）
  - 優先順位・上書き・不明なアイテムの扱いはアイテムのアスペクト定義（§2.3）と同じ。`"capacity": 0` は「注入できない」を明示する
  - 初期値: アイテムタグ `thaumory:arcane_iron_equipment`（魔鉄の装備 9 種）が 3、`thaumory:aether_silver_equipment`（天銀の装備 9 種）が 5。それ以外（バニラの装備を含む）は容量なし
  - 対応表はサーバーが読み、参加したときと datapack を読み直したときにクライアントへ送る（ツールチップのため）
- 効果のコスト: 組み合わせのファイルの `"capacity": n`（省略すると 1）。レベルでは変わらない
  - 初期値: 灯火 1・成長 1・浄化 2・結界 2・治癒 2・引き寄せ 2・テレポート 3・天候 3・軽やかさ 1・息吹き 1・夜目 1・束縛 2・衰弱 2・灼光 2・採掘 3（M2-23）
- 使用量 = 焼き付けた効果のコストの合計。コストは焼き付けたときの値を記録し、あとで datapack が変わっても変えない
  - 同じ効果を焼き直すときは、置き換えられる古い分を除いて数える。使用量 + 新しいコストが容量を超えるなら注入しない
- ツールチップ: 容量のあるアイテムに「容量 使用量/容量」を出す（焼き付けた効果の一覧の上）

#### 装備での働き（M2-8）

- 「装備している」= 利き手・オフハンド・防具の 4 か所のどこかにある。同じ効果を複数の場所に装備していても重ならず、一番高いレベルだけが働く
- パッシブは装備しているだけで働き、何も消費しない。アクティブは専用のキーで使い、品に内蔵した Essentia を払う
- 効果ごとの働き（数値は組み合わせのファイルの `item_settings` で変えられる）

| 効果 | 種類 | 働き |
|---|---|---|
| 治癒 | パッシブ | 5 秒ごとにレベル分回復する（1 = ハート半分）。スロット 3 が Bestia なら、自分の代わりに半径 4 の動物 |
| 結界 | パッシブ | 0.25 秒ごとに、半径 2 + レベルの対象（スロット 3。陣と同じ）を自分から外へ押し出す |
| 引き寄せ | パッシブ | 0.25 秒ごとに、半径 3 + レベルの落ちているアイテムを自分へ動かす。スロット 3 のアスペクトがあれば、それを含むアイテムだけ |
| 成長 | パッシブ | 1 秒ごとに、半径 2 + レベル。Herba = 作物をランダムティック 1 回分育てる（レベル × 2 列）、Bestia = 子どもの動物を 20 × レベル tick 大人に近づける |
| 灯火 | パッシブ | スロット 3 が空: 暗い場所（ブロックの明るさ 7 以下）にいると、頭の高さに見えない光源（明るさ 15）を置く。離れたら消す。Umbra: 利き手の品で攻撃した相手に「暗闇」を 3 + レベル 秒 |
| テレポート | アクティブ | 同じ次元で、同じ組み合わせ（Arcanum + Aer + 同じスロット 3）の陣が成立している Core のうち、一番近いものの上へ運ぶ。行き先が無ければ何も払わない |
| 天候 | アクティブ | 陣と同じく天候を変える（5 分 × レベル）。空の見えない次元では何も払わない |
| 浄化 | アクティブ | 今いるチャンクの Flux を 10 × レベル 減らす |
| 軽やかさ（M2-23） | パッシブ | 移動速度上昇（レベルぶん）。装備している間は落下のダメージを受けない |
| 息吹き（M2-23） | パッシブ | 水中呼吸とイルカの好意 |
| 夜目（M2-23） | パッシブ | 暗視 |
| 束縛（M2-23） | パッシブ | 利き手の品で攻撃した相手に、移動速度低下 IV（レベルごとに 1 つ上がる）を 2 + レベル 秒 |
| 衰弱（M2-23） | パッシブ | 利き手の品で攻撃した相手に、衰えと弱体化を 3 + レベル 秒 |
| 灼光（M2-23） | アクティブ | 半径 4 + レベルの敵対 mob すべてに 4 × レベルの火のダメージを与え、3 秒燃やす。敵対 mob がいなければ何も払わない |
| 採掘（M2-23） | アクティブ | 見ているブロック（手の届く距離）の面を中心に、面に沿って一辺 1 + 2 × レベルの正方形を、奥へ 3 マス掘る。掘れるものは陣と同じ（鉄のつるはし級、中身を持つブロック・液体は残す）で、落ちる品は足元に出す。掘れるものが無ければ何も払わない |

- 軽やかさ・息吹き・夜目は陣と同じく、状態効果を 1 秒ごとにかけ直す。外しても少し残る（軽やかさ・息吹きは 3 秒、夜目は 11 秒）。スロット 3 は見ない（自分にだけ効く）

- アクティブ効果は 1 つの品に 1 つまで。違うアクティブ効果が入っている品には注入しない（アクションバーに「この品にはすでに使う効果がある」）。同じ効果の焼き直しはよい
- 使う: キー割り当て「注入の効果を使う」（既定 V）。利き手の品のアクティブ効果を使う。利き手に無ければ、着ている防具を頭から足の順に見て最初に見つかったもの。結果（使った・Essentia が足りない・行き先が無い）はアクションバーに出す
- 内蔵: アクティブ効果の組み合わせのスロット 1・2 のアスペクトを、それぞれ容量（初期 64、`circle.json` の `infusion.item_essentia`）まで品に内蔵する
  - 1 回の消費は、組み合わせのファイルの `item_cost`（初期: テレポート 4・天候 8・浄化 4・灼光 4・採掘 4）を両方のアスペクトから。注入したときの消費の倍率をかけ（四捨五入、最低 1）、焼き付けたときの値を品に記録する
  - ツールチップに内蔵の量を出す（「内蔵: Arcanum 12/64」。未判明のアスペクトは紋字）。アクティブ効果には「（使う）」を付ける
- 補充: 瓶か充填の陣
  - 瓶: 利き手に瓶、オフハンドに品を持ってスニーク + 右クリックで、瓶の中身のうち品が内蔵するアスペクトを入るだけ注ぐ（Rune と同じ操作。§4.2）。入らないものは瓶に残る
  - 充填の陣: Arcanum + Vinculum（スロット 3 は空か任意のアスペクト）の持続型の陣。1 秒ごとに、Core の Essentia から台座の品が内蔵するアスペクトを、それぞれ「4 × 強度（切り上げ）」まで移す（`per_second`）。Core にはパイプで供給できる。範囲にいるプレイヤーが手に持つ杖にも注ぐ（§17.7）
  - 充填の陣の効果は焼き付けられない。焼き付けられない効果の陣では、台座に品があっても杖は注入の代わりにいつもどおり起動・停止する

### 10.3 陣の効果を固定化したもの

| 種類 | 作り方 | 特徴 |
|---|---|---|
| 巻物 | 白紙の巻物に注入 | 使い捨て。Essentia は不要。1枚に1効果 |
| 護符 | 空の護符に注入 | 繰り返し使える。Essentia を内蔵して消費する。インベントリに入れるだけでパッシブが効く |
| 陣石（便利ブロック） | 空の陣石に注入 | 設置すると小さな範囲（半径4程度）で効果を発揮する。修飾はできない。Essentia は配管で供給する |

#### 陣石（M2-11）

- 空の陣石: 作業台で、上の中央に結晶のかけら、真ん中に魔鉄のインゴット、残りの 7 マスに石レンガ。1 つできる。16 まで重なる
- 注入の陣の台座に 1 つ載せて杖で焼き付けると「治癒の陣石」「灯火の陣石」のようになる。消費と失敗の確率はほかの注入と同じ
  - 焼き付けられるのは持続型の組み合わせすべて（農業・工業・防衛・生活・封じ込めも入る。装備に焼き付けられない効果も入る）。充填は台座の品に注ぐ効果なので除く。ランク 2 以上が要る組み合わせも除く（陣石はランク 1 として扱う）。焼き付けられなければ「この陣の効果は陣石に焼き付けられない」
  - 焼き付けるのは組み合わせ（Rune の並び）。動くときの消費の間隔・設定・働いた分の Flux は、組み合わせのファイルの値を使う
  - 焼き付けた陣石は重ならない。ツールチップに効果の名前（とスロット 3 のアスペクト）を出す
- 置く: Core と同じく床・壁・天井のどの面にも置ける
- 働き: 半径 4（`circle.json` の `stone_radius`）・強度 1 で働く。範囲の中心は陣石。修飾・ランク・注入のレベルは関係せず、不安定度は 0
  - Essentia がある間は常に動く。レッドストーン信号を受けている間は止まる（止まるときは陣と同じく効果の後始末をする）
  - Essentia は中に持つ。焼き付けた組み合わせのアスペクト（Core の Rune と同じく、スロット 3 も含む）を、それぞれ Core と同じ容量（`essentia_capacity`、初期 64）まで。配管から受け取り、瓶からも注げる。配管では取り出せない（瓶では汲める。Core と同じ）
  - 消費は持続型の陣と同じ: 組み合わせの間隔ごとにスロット 1・2 を 1 ずつ。足りなければ止まり、また入れば動き出す
- 壊す: 焼き付けたままの陣石として落ちる（置き直せる）。中の Essentia は Core と同じく Flux になる
- ルーペ: 効果の名前・動いているか（止まっているなら理由: Essentia 不足・信号）・中の Essentia
- 見た目: 描いた面に貼りつく石板。動いている間だけ、上に Core の回る円が 2 重に浮かぶ（内側がスロット 1、外側がスロット 2 のアスペクトの色。ゆっくり上下する）。テクスチャは仮

#### 巻物（M2-9）

- 白紙の巻物: 錬金術で 紙 + Arcanum 2。章「魔法陣」で開放する。16 まで重なる。容量 3（`infusion_capacity` の対応表。どの効果も 1 つは入る）
- 白紙の巻物に注入すると「巻物」に変わる。巻物には容量が無いので、1 枚に 1 効果。巻物も 16 まで重なる（同じ効果・レベル・スロット 3 のものどうし）
- 使う: 手に持って右クリックで 1 回発動し、1 枚減る。Essentia は要らない。行き先が無いなどで発動しなければ減らない
- 巻物は装備には数えない（手に持っていてもパッシブは働かず、キーでも使わない）
- 効果ごとの働き（数値は組み合わせのファイルの `item_settings` の `scroll_*`）

| 効果 | 働き |
|---|---|
| テレポート・天候・浄化・灼光・採掘 | 装備のアクティブ効果と同じ |
| 治癒 | その場で 4 × レベル 回復する。スロット 3 が Bestia なら、自分の代わりに半径 4 の動物 |
| 結界 | 半径 4 + レベルの対象を強く押し出す |
| 引き寄せ | 半径 8 + レベルの落ちているアイテム（スロット 3 のフィルタ）を足元へ運ぶ |
| 成長 | 半径 3 + レベル。Herba = 作物すべてにランダムティック 2 × レベル 回、Bestia = 子どもの動物を 1200 × レベル tick 大人に近づける |
| 灯火 | 空 = 半径 8 の暗い地面に見えない光源を 4 × レベル 個置く（残る）。Umbra = 自分以外の半径 8 の生き物に「暗闇」10 秒 |

- API: 注入効果は巻物で使えるかどうかと、巻物での働きを持つ。巻物で使えない効果は白紙の巻物に注入しない（「この陣の効果は焼き付けられない」）

#### 護符（M2-10）

- 護符: 作業台で、金塊 4（左右に 2 段）+ 魔鉄のインゴット（下の中央）。スタックしない。容量 2（`infusion_capacity` の対応表）。何も焼き付けていないものが「空の護符」
- 持ち物（ホットバー・オフハンド・防具を含む）のどこかにあるだけで、焼き付けたパッシブ効果が働く。持ち物の護符はすべて効き、同じ効果は装備と合わせて一番高いレベルだけが働く。攻撃したときの効果（灯火の Umbra）は、利き手に持っているときだけ
- アクティブ効果は装備と同じく内蔵した Essentia を払う（1 つの品に 1 つまで。補充も瓶か充填の陣）。キーは 利き手 → 防具（頭から足）→ 持ち物の護符（スロット順）の順に見て、最初に見つかったアクティブ効果を使う

### 10.4 専用の注入装置（M5、エンドコンテンツ）

- 名前は「大いなる注入の祭壇」。どちらの道でも使う（§17.10）
- 大型のマルチブロック（中央の祭壇 + 周囲の柱）
- 容量の上限を超えられる（超えるごとに失敗の確率が上がる）、複数の効果を同時に注入できる、ランク3の素材（光は暁金、闇は宵鋼。§17.9）を作れる
- 失敗すると装備が壊れる可能性がある
- 詳細は M5 の実装時に決める

## 11. Node（M5）

- ワールド生成でまれに配置される魔力の結節点。ルーペでスキャンしないと見えない
- 1〜3種類のアスペクトを持ち、バイオームによって傾向がある
- 時間とともに回復し、汲み上げすぎると枯渇して回復が遅くなる
- 汲み上げ装置で Essentia を取り出せる。Flux は出ないが、量と種類が限られる
- 封印の瓶で移設できる。失敗すると Node が消滅し、大量の Flux が出る
- チャンクごとの Aura は入れない
- どちらの道でも同じように使う（§17.10）。無線輸送（§8.3）の送り手と受け手は「共鳴の台」

## 13. データ駆動の境界

- 数値と対応関係は JSON（datapack）、振る舞いはコード
- JSON: アイテム → アスペクト、アスペクトの木構造、陣の組み合わせ → 効果の種類、消費量、Flux の閾値・減衰率、ポーションマップの効果の座標、リサーチツリー・ヒント
- コード: 効果のロジック（テレポートする、光を置く、など）
- `/reload` で反映できるようにする

## 14. 非機能要件

- 言語: 日本語と英語（`ja_jp.json` / `en_us.json`）。本の文章も両方
- 設定: ゲームバランスの数値は datapack。クライアント側の設定（HUD の位置など）だけを config ファイルにする
- 性能: 陣のスキャン、配管のネットワーク、Flux の処理は毎 tick ではなく一定の間隔で行う
- テスト: アスペクトの推定・陣の判定・Flux の計算などのロジックは Minecraft に依存しない純粋な Java のクラスに分け、単体テストを書く。ゲーム内の動作は Fabric GameTest で確認する

## 17. 遊びの流れとコンテンツの計画（2026-09-24）

基盤（陣・配管・注入・装備）ができたので、遊びの流れから足りないコンテンツを決めた。細かい数値は各タスクに着手するときに決め、この節を更新する。

### 17.1 方針

- 最終目標: 魔術で整えた拠点。陣・配管・陣石で自動で回る工房と拠点を作る。Flux を出さずに回すのが腕の見せ所
- 物語: 世界の成り立ちの謎を、碑文を読み解いて明かす本筋がある。光と闇の道を選び、封印の間の儀式で一区切りを迎える。そのあとは拠点を極める遊びに戻る（§17.8）
- Flux: 付き合うコスト。放っておくと拠点が蝕まれ手間が増えるが、浄化・封じ込め・管理で抑えられ、抑える仕組みづくりが遊びになる。世界を滅ぼすほどには広がらない。物語では「封印のほころびから漏れる、元に戻ろうとする力」という意味を持ち、終盤は資源にもなる
- 入口: ワールドで魔力に出会う。最初の一歩を発見にする
- 研究: 試行錯誤が主役。答えは見せず、ヒントは断片的に
- Essentia: Crucible に溶かすのが中心のまま、投入の自動化（ホッパー・引き寄せ・溶解の陣）で量を集める。何を育てて溶かすかを農業・牧場とつなぐ

### 17.2 流れ

- 序盤: 洞窟で魔力の結晶に出会う → そのかけらでルーペを作り、覗く → Crucible → Rune → 最初の陣（灯火・治癒）。地表で古い陣の跡を見つけると近道になる
- 中盤: 配管と瓶で Essentia を流し、農業・工業・防衛・生活の陣で拠点を回す。Flux が溜まり始め、浄化と封じ込めで扱う。装備・巻物・護符・魔導アイテム・杖の焦点で自分を強くする。陣のランクを上げる。埋もれた書庫で碑文を読み、真相を知って光か闇の道を選ぶ
- 終盤: 道の章と品、ランク 3 の素材と大型の注入装置、Node と無線輸送。封印の間を探し、大陣の儀式を成して Nihil を知る（M5）
- 儀式のあと: Nihil の品とランク 5 の陣で拠点を極める

### 17.3 入口（M2-17・M2-18）

- 魔力の結晶: 洞窟の壁や天井に生える、光る結晶のブロック（ワールド生成）。掘ると「結晶のかけら」になる。かけらは Arcanum を多く含む。ルーペのレシピのガラス板をかけらに置き換える（ルーペを作るには結晶を見つける必要がある）
  - ブロック: アメジストの房のように、床・壁・天井の面に生える向きのある房。明るさ 6。水に浸かれる。育たない（掘り尽くすと増えない）。しっかりした面にだけ置け、支えが無くなると壊れる
  - 生成: オーバーワールドの地下（y −60〜16）の洞窟で、石系のブロック（`#minecraft:base_stone_overworld`）の面に数個ずつの群れで生える。回数・高さ・群れの大きさは `data/thaumory/worldgen/` の JSON
  - 掘る: アメジストの房と同じ。つるはしでかけら 2〜4（幸運で増える）、つるはし以外は 1、シルクタッチで結晶そのもの
  - アスペクト: かけら = Arcanum 4 + Lux 1、結晶 = Arcanum 8 + Lux 2
- 古い陣の跡: 地表にまれに生成される小さな構造物。崩れたリングと Rune の挿さった Core、小箱（写し・空の Rune・チョークなど）。見つけなくても進めるが、見つけると得をする
  - 形: 7×7 に収まる。中央に石レンガの 5×5 の床（苔むした・ひびの入ったレンガが混ざり、ところどころ欠けて地面が見える）。床の中央に Core、そのまわりに 2 マス欠けた内側のリング、その外に切れ切れの半径 3 の円のリング（M2-35 で四角から作り直す。床の外にかかる所は地面に描く）。崩れた柱が 2 本、角に小箱
  - 種類は 3 つ。Core には動く組み合わせの Rune が 2 つ挿してある: 灯火（Lux + Ignis）・治癒（Vita + Ordo）・浄化（Ordo + Lux）。Essentia は空。内側のリングを描き直して Essentia を注ぐと動く
  - 頻度: 構造物の配置で間隔 20 チャンク・最小距離 8 チャンク（バイオームを絞るぶん、廃墟のポータルより少し多いぐらいになる。一番近い跡までおよそ 300 ブロック）。バイオームは平原・森・タイガ・サバンナ・砂漠・草原など地表の陸地（バイオームタグ `thaumory:has_structure/old_circle`）。海・川・山頂・氷原には出ない
  - 小箱（ルートテーブル `thaumory:chests/old_circle`）: アスペクトの写し 1〜2 枚（Primal が多く、Lux・Ordo・Herba・Vinculum も出る）、まれに跡の 3 種の陣の写し、空の Rune 1〜2、耐久の減った基本のチョーク、結晶のかけら 2〜4、紙・イカスミ・金塊
  - 構造物・配置・テンプレートの一覧・ルートテーブルは datapack の JSON。テンプレートは `data/thaumory/structure/old_circle/*.nbt`

| 農業 | 潤い | Aqua + Herba | 持続 | 農地を湿らせる。火を消す |

- 農業の陣（M2-19）: スロット 3 はどれも空だけ。消費の間隔は今までと同じ 10 秒。注入はできない（容量 0）
  - 走査: 収穫と潤いは、範囲の列（Core から東西南北に範囲の分）を端から順に見ていく。1 秒に「8 × 強度（切り上げ）」列ずつ進み、どこまで見たかを Core に覚える。列ごとに Core の高さ ± 範囲のマスを見る（`columns_per_level`）
  - 収穫: 見た列の育ちきった作物を刈る。収穫物はそのマスに落ちる
    - 畑の作物（`#minecraft:crops` の作物。茎とピッチャーの苗を除く）・ネザーウォート・カカオ: 刈って、収穫物から種（そのブロックを植えるアイテム）を 1 つ減らして植え直す。種が出なければ植え直さない
    - スイカ・カボチャ: 実った茎がつながっている実だけを刈る（茎は残す）
    - サトウキビ・サボテン・竹: 根元の 1 マスを残して上を刈る
    - スイートベリー: 実だけを摘む（茂みは実の無い段階に戻る）
  - 繁殖: 10 秒ごと（`interval_seconds`）に「強度（切り上げ）」組の大人の動物をつがわせる（恋に落ちた状態にする。あとはバニラの繁殖と同じ）。組は同じ種類の、恋に落ちられる 2 頭。範囲内のその種類が 16 頭（`max_per_kind`、子どもも数える）以上なら、その種類はつがわせない
  - 潤い: 見た列の農地を湿らせきり（水気 7）、火のブロックを消す。1 秒ごとに、範囲内の燃えている生き物の火を消す
- 工業の陣（M2-20）: 採掘だけ巻物とアクティブで注入できる（§10.2）。ほかは注入できない（容量 0）。精錬・仕分け・溶解は範囲内の落ちている品を扱い、1 秒に「4 × 強度（切り上げ）」個（仕分けはスタック）まで（`items_per_level`）
  - 精錬: スロット 3 は空だけ。かまどのレシピで焼き、できた品はその場に落ちる。経験値はかまどと同じだけ出る。焼いてできた品は二度焼かない（丸石 → 石 → なめらかな石と進まない）
  - 採掘（起動型、消費 1）: スロット 3 は空だけ。陣の奥（描いた面の裏側。床なら下、天井なら上、壁なら壁の奥）の「一辺 2 × 範囲 + 1」の正方形を、起動するたびに 1 層ずつ掘り進む。面のすぐ裏の 1 層は支えとして残す。どこまで掘ったかは Core が覚える
    - 起動すると、その層を 1 秒に「4 × 強度（切り上げ）」ブロックずつ掘る（`blocks_per_level`）。掘っている最中に杖で右クリックする（デバッグコマンドの `stop` でもよい）と止まる。次に起動するとその層の続きから掘る
    - 8 ブロック（`blocks_per_essentia`）掘るごとに、Bellum と Terra を 1 × 消費の倍率（四捨五入、最低 1）ずつ Core から払う。払えなければそこで止まり、次に起動するとその層の続きから掘る
    - 掘るのは鉄のつるはしで掘れるブロック（`#minecraft:incorrect_for_iron_tool` に入らず、壊せるもの）。中身を持つブロック（チェストなど）・液体・空気は残す。掘れるものが無い層は飛ばして次の層を掘る（1 回に 16 層まで探す）
    - 落ちる品は鉄のつるはしで掘ったときと同じ。掘った分ずつ陣の前（Core のマス）に出す
    - 掘れるものが見つからなければ発動せず、何も消費しない
  - 仕分け: スロット 3 は空か任意（そのアスペクトを含む品だけ）。範囲内の容器（チェスト・樽・シュルカーボックス・ホッパーなど、中身を持つブロック）へ入れる。入れ先は、同じ品をすでに入れている容器が先、無ければ Core に近い順。入りきらない分はその場に残る
  - 溶解: スロット 3 は空か任意。品を 1 個ずつ溶かす。得られる量は Crucible と同じ割合（§3、手動定義 100%・推定 75%、アスペクトごとに切り捨て）。スロット 3 のアスペクトは Core に溜め（Core の容量まで）、それ以外と入りきらない分は 1:1 で Core のチャンクの Flux になる。スロット 3 が空ならすべて Flux。アスペクトの無い品は溶かさない
- 防衛の陣（M2-21）: 持続型の消費の間隔は今までと同じ 10 秒。束縛・衰弱・灼光は注入できる（§10.2）。誘引は注入できない（容量 0）。プレイヤーは対象にならない
  - 誘引・束縛: スロット 3 で対象を選ぶ。空・Chaos = 敵対 mob、Bestia = 動物、Mors = アンデッド（結界と同じ）
    - 誘引: 0.25 秒ごとに、範囲内の対象を Core の前へ向かって「0.6 × 強度」の勢いで押す（`pull_per_level`、最大 1）。Core から 1.5 マス以内まで来たら動かさない。しるしは動かした対象に 1 秒に 1 回
    - 束縛: 1 秒ごとに、範囲内の対象に移動速度低下をかけ直す（レベルは 3 + 強度の切り上げ。強度 1 で IV）。範囲を出ても 3 秒残る。しるしは新しくかけたとき
  - 灼光（起動型、消費 4）: スロット 3 は空だけ。範囲内の敵対 mob すべてに「4 × 強度」の火のダメージを与え、3 秒燃やす。範囲に敵対 mob がいなければ発動せず、何も消費しない。しるしは当てた 1 体ごと
  - 衰弱: スロット 3 は空だけ。1 秒ごとに、範囲内の敵対 mob に衰え（ウィザーの効果）と弱体化をかけ直す。衰えは体力 0 まで削り、アンデッドにも効く。範囲を出ても 4 秒残る。しるしは新しくかけたとき
- 生活の陣（M2-22）: 消費の間隔は今までと同じ 10 秒。軽やかさ・息吹き・夜目はパッシブとして注入できる（§10.2）。護りは注入できない（容量 0）
  - 軽やかさ・息吹き・夜目: スロット 3 で相手を選ぶ。空 = プレイヤー、Bestia = 動物、Chaos = 敵対 mob。1 秒ごとに範囲内の相手へ状態効果をかけ直す（粒は出さない）。範囲を出ても少し残る（軽やかさ・息吹きは 3 秒、夜目は 11 秒。暗視は残り 10 秒を切ると点滅するため）
    - 軽やかさ: 移動速度上昇（レベルは強度の切り上げ）。着地したときに範囲内にいる相手は、落下のダメージを受けない
    - 息吹き: 水中呼吸とイルカの好意
    - 夜目: 暗視
    - しるし: その状態効果を持っていなかった相手に新しくかけたとき、軽やかさで落下のダメージを消したとき
  - 護り: スロット 3 は空だけ。範囲内では次のようになる
    - 爆発でブロックが壊れない。誰の爆発でも、爆発の中心が範囲の外でも、範囲内のマスは残る（範囲外のマスは壊れる）。生き物へのダメージとノックバックはそのまま。範囲内のブロックを守った爆発 1 回につき、爆発の中心にしるし
    - 範囲内にいる mob（飛び道具を含む）にとって、ゲームルール mobGriefing が false になる（エンダーマンが持ち去らない、ゾンビがドアを壊さない、羊が草を食べない、作物を踏み荒らさない、など）。判定は mob のいる場所で行う。バニラは壊そうとしたかを知らせないので、しるしは出さない
- 注入（M2-23）: 品で意味のあるものだけ焼き付けられる。軽やかさ・息吹き・夜目 = パッシブ（自分にだけ）、衰弱・束縛 = 利き手で攻撃した相手に、灼光・採掘 = 巻物とアクティブ。収穫・繁殖・潤い・精錬・仕分け・溶解・誘引・護り・封じ込めは陣だけ
- ヒントは効果ごとに 1 つ（今までと同じく、スロット 1・2 のアスペクトを両方判明させると現れる）

### 17.5 Flux の結晶（M2-24）

- 封じ込めの陣が生む。中に Flux を持つ危ない品で、水や溶岩に落ちる・消えると中の Flux がそのチャンクに戻る
- 汚染のアスペクト（M2-13）の源で、ランク 3 の素材（M5）の材料になる
- 封じ込めの陣（Vinculum + Chaos、持続型）: スロット 3 は空だけ。消費の間隔は 10 秒。注入はできない（容量 0）。働いた分の Flux は 0
  - 1 秒ごとに、範囲にかかるチャンクそれぞれから Flux を「強度 × 1」吸う（`flux_per_second`。浄化の倍の速さ）。吸った分は Core に貯める
  - 貯めた分が 10 に達するごとに（`flux_per_crystal`）、Flux の結晶を 1 つ Core のマスに落とし、Core にしるしを出す
  - 止めたとき（Essentia 切れ・陣が崩れる・Core を壊すを含む）、貯めていた 10 未満の分は Core のチャンクに戻す
- Flux の結晶: 1 つに Flux 10 を持つ。16 まで重なる。アスペクトは Sordes 4（§2.2）
  - 割れる: 落ちている結晶が、溶岩・火・爆発・サボテンなどで壊れる、奈落に落ちる、5 分たって消える、水に触れると割れて、中の Flux（10 × 個数）がそのチャンクに戻る。音と紫の粒子を出す
  - 容器・持ち物の中では割れない。ホッパーで吸う・拾う・まとまる（同じ品どうしが 1 つになる）ときも割れない
  - Crucible・溶解の陣で溶かすと、アスペクトに加えて中の Flux もそのチャンクに出る

### 17.6 魔導アイテム（M2-25〜M2-28）

- 暴きのモノクル: 頭に着けるルーペ。手に持たなくても Flux・容器の中身・パイプが見える。スキャンはルーペのまま
  - 作り方: Crucible の錬金術で、触媒は魔術のルーペ、Lux 12 + Arcanum 8。章「暴きのモノクル」で開放
  - 頭の枠に着ける（兜とは両立しない）。着けると右目にモノクルが見える。耐久値なし・防御なし
  - 着けている間は、右上の Flux と、容器（Crucible・瓶）・パイプ・陣の診断が出る。ほかのブロックの名前とアスペクト（§7.2）は、常に出るとうるさいので出さない（ルーペを持てば出る）。スキャンはできない（ルーペを持って右クリック）
- Essentia の腕袋: 瓶を数本入れて持ち歩く。装備・護符の内蔵 Essentia が減ると、ここから自動で補充する
- 探知の振り子: 選んだアスペクトを多く含むもの（鉱石・結晶・古い陣の跡など）の方を指す
- 携帯の陣板: 小さな陣を刻んだ板。Rune を挿して持ち歩き、持続型の陣を自分の周りの狭い範囲に張る。内蔵 Essentia を使う

### 17.7 杖の焦点（M2-29・M2-30）

- 杖に焦点を付けると、空中への右クリックで呪文を撃つ。杖に内蔵した Essentia（M2-12）を焦点のアスペクトで払う。Core への右クリックは今までどおり
- 焦点（7 種）

| 系統 | 焦点 | アスペクト | 働き（概要） |
|---|---|---|---|
| 戦い | 火 | Ignis | 火の玉。当たった相手を燃やす。地形は壊さない |
| 戦い | 凍気 | Aqua | 冷気の波。相手を遅くし、水を凍らせる |
| 戦い | 雷 | Tempestas | 視線の先へ雷撃。近くの敵へ連鎖する |
| 作業 | 掘削 | Terra + Bellum | 離れたブロックを掘る（採掘の段階は杖の素材で決まる） |

| 作業 | 交換 | Ordo + Chaos | 狙ったブロックを手持ちのブロックに置き換える |
| 作業 | 光 | Lux | 狙った場所に消えない光源を置く |

#### 仕組み（M2-29）

- 焦点はアイテム（1 種類 1 アイテム、スタックしない）。杖は付けた焦点を 1 つ、コンポーネントに持つ
- 付け外し: キー割り当て「焦点を選ぶ」（既定 G）。利き手に杖を持ってキーを押している間、円形のメニューが開く
  - 円に並ぶのは、持ち物にある焦点（種類ごとに 1 つ、スロット順）と、焦点を付けているときの「外す」。真ん中に今の焦点
  - マウスを動かした向きの項目を選び、キーを離すと決まる。選んだ焦点は持ち物から杖へ、前の焦点はその焦点があったスロットへ戻る。「外す」は持ち物へ（入らなければ足元に落とす）。真ん中のまま離すと何もしない
  - 持ち物に焦点が無く、杖にも付いていなければメニューは開かず、アクションバーに「持ち物に焦点が無い」
- 撃つ: 焦点を付けた杖で、空中か Core 以外のブロックを右クリック。Core への右クリックは今までどおり（陣の操作・注入）
  - 1 回の消費は焦点ごとのアスペクトと量（`cost`）。どれか 1 つでも足りなければ撃たず、アクションバーに「Essentia が足りない」
  - 狙う先が無いなど呪文が働かなければ何も払わない
  - 撃ったあと、焦点ごとの待ち時間（`cooldown`、tick）は杖を使えない（ホットバーに待ち時間の表示）。Core への操作もその間はできない
  - 威力は杖の芯の `power`。採掘の段階は芯の `incorrect_for`（掘削の焦点が使う）
- 内蔵: 受け付けるのは付けた焦点の `cost` のアスペクトだけ。量はアスペクトごとに金具の `essentia` まで
  - 焦点を替えても、入っている Essentia はそのまま残る（前の焦点に戻せばまた使える）。今の焦点が使わないアスペクトは補充されない
  - 金具を内蔵量の少ないものに替えて容量を超えたときは、超えた分も残る（使って減るまで補充されない）
  - ツールチップに付けた焦点の名前と、内蔵の量（「内蔵: Lux 12/16」。今の焦点が使うアスペクトを先に、ほかに残っているものもあれば出す。未判明のアスペクトは紋字）
- 補充
  - 瓶: 利き手に瓶、オフハンドに杖でスニーク + 右クリック。瓶の中身のうち、杖が受け付けるアスペクトを入るだけ注ぐ（装備と同じ操作。§10.2）
  - 充填の陣: 動いている間、陣の範囲にいるプレイヤーの利き手・オフハンドの杖にも注ぐ。杖 1 本ごとに台座の品と同じいきおい（1 秒に 4 × 強度）で、Core の Essentia から
- 形式: `data/<ns>/thaumory/wand_focus/*.json` に 1 ファイル 1 焦点。`/reload` で読み直し、クライアントへ送る（ツールチップとメニュー）
  - `{"item": "thaumory:light_focus", "effect": "thaumory:light", "cost": {"thaumory:lux": 1}, "cooldown": 10, "settings": {"range": 32}}`
  - `effect` は API で登録した呪文の ID（拡張ポイント 11。§12）。`settings` は呪文ごとの数値
- 作り方
  - 空の焦点: 作業台で、金塊 4（上下左右）+ 結晶のかけら（真ん中）。1 つできる。空の焦点は呪文を持たず、杖に付けられない
  - 各焦点: Crucible の錬金術で、空の焦点を触媒に焦点のアスペクト。光の焦点は Lux 12
  - 章「杖の焦点」（分野「金属と装備」。「魔術の金属」の次。条件: グロウストーンダストをスキャン）で、空の焦点と光の焦点を開く。M2-30 の焦点は同じ章か続きの章で開く

#### 光の焦点（M2-29）

- 視線の先（`range` 32 マス以内）のブロックを狙い、当たった面の手前のマスが空気なら、見えない光源（明るさ 15）を置く。置いた光源は消えない
  - ブロックに当たらない・手前のマスが空気でなければ撃たない（何も払わない）
  - スニークしながら撃つと、狙ったマスとその周り 1 マスにある見えない光源を 1 つ消す（何も払わない。消せるものが無ければ撃たない）
- 消費は Lux 1、待ち時間 10 tick。芯の威力は使わない
- 撃つと、杖から狙った場所まで Lux の色の光の粒が並び、置いた場所で粒が弾ける

### 17.8 物語（M5。2026-09-25）

- 世界の成り立ち: 世界は、分かれる前の無色の力が 6 つの Primal に割れてできた。割れ目の向こうが虚空（闇）。打ち消しで生まれる Flux は、元の姿に戻ろうとする力
- 古い民: 古い陣の跡を残した人々。闇を世界から切り離して虚空に封じた。光だけの世界は長く保たず、彼らは消えた。Flux は封印のほころびから漏れている
- 見せ方: 序盤は「Flux ＝ 闇 ＝ 悪、浄化 ＝ 光 ＝ 善」と思わせ、碑文を読み進めると思い込みが崩れる
- 碑文: 遺跡の壁にある碑文のブロック。ルーペで読むと本の新しいタブ「碑文」に写る（持ち帰らなくてよい）
  - 紋字で書かれ、語ごとにアスペクトが結び付いている。判明したアスペクトの語から読めるようになり、全部読めると章が開く。読めるかどうかは読む人の知識で決まる
  - 紋字はアスペクトの名前の暗号ではない（§6.1）。碑文の語が読めるのは知識による
- 碑文のある場所。進むほど深くなる
  - 序盤: 古い陣の跡（§17.3）に短い碑文
  - 中盤: 埋もれた書庫。地下の中くらいの構造物。碑文 3〜4 つと小箱
  - 最後: 封印の間
- 本の分野: 物語の章は新しい分野に置く（名前は着手するときに決める）
- 光と闇の道
  - 真相の章を読むと、光（Lux 系）と闇（Umbra 系）の誓いの陣が示される。最初に起動したほうの道に進む。道はプレイヤーごと
  - 誓いの陣と大陣には古紋のチョーク（古い民の紋様）が要る。作り方は碑文で分かる
  - 道ごとに、途中の章・レシピと結末が違う。共通の章はそのまま残る
  - 乗り換え: 儀式の前なら、もう一方の誓いの陣で道を変えられる。前の道の章は未完了に戻り、そのレシピは使えなくなる（作った品は残る）。その場所に大量の Flux が出る
  - 道の章は知識の写しで渡せない（章は書き写せない。§6.3）
- 封印の間: 地下深く（深層岩の高さ）にまれに複数ある。古代都市よりまれ
  - 最後の碑文を読むと、探知の振り子（M2-27）で「封印」を選べるようになり、一番近い封印の間を指す
  - 中央に壊れた大陣の跡と祭壇、周りに 6 本の柱。祭壇は作れない特別な Core（§4.6）
- 大陣の儀式
  - 壊れた大陣を古紋のチョークで描き直し、柱に Primal 6 種、祭壇に道のアスペクト（光は Lux、闇は Umbra）を配管で流し込み続ける。その間、虚空の残滓の群れと Flux の噴き出しをしのぐ
  - 新しい品よりも、ここまでに作った配管と陣の腕試しにする
  - 1 か所につき 1 回。失敗（Essentia が尽きる・陣が崩れる）すると払った分を失い、封印の間に大量の Flux が出る。浄化すればやり直せる
  - 結末は儀式を成した人にだけ及ぶ（ワールドは変わらない）。Nihil（§2.2）が判明し、道の結末の章が開く
- 文章: 碑文と章の文は Claude が日本語と英語で下書きし、ユーザーが直す
- 数値・構造物の形・誓いの陣の組み合わせは、着手するときに決める

### 17.9 光と闇の道の品（M5）

- どちらの道にも同じ役割の品があり、違うのは使う力と癖
  - 光: Essentia を多めに払う。確実で静か
  - 闇: Flux を燃料に払う。速く強いが、結果に揺らぎや副産物が出る
- 名前は和の言葉で光と闇の対にする（下の名前は仮）

| 役割 | 光 | 闇 |
|---|---|---|
| 素材 | 暁金: 天銀 + 光の第 3 層のアスペクト | 宵鋼: Flux の結晶 + 闇の第 3 層のアスペクト |
| 自動クラフト | 組成の陣: 範囲内の容器の材料で、見本どおりに作業台のレシピを作り続ける | 変容の陣: 材料をまとめて変える。速いが、ときどきアスペクトの近い別の品になる |
| Flux の処理 | 封印の陣: 範囲内の陣が働いても Flux を出さない。そのぶん消費が増える | 喰らいの陣: 範囲の Flux を吸い、抱えた陣（子の陣）の燃料にする |
| Nihil の入手 | 封瓶: 打ち消しで生まれるはずの Flux を Nihil として封じる | 虚の炉: Flux の結晶を溶かし、Nihil と Essentia を取り出す |
| 守りと戦い | 聖域の陣: 敵対 mob が入れず、入り込んだ虚空の残滓は消える | 使役の陣: 虚空の残滓を従え、範囲内の敵と戦わせる |
| 装備 | 暁金の装備一式: 守り寄り。Flux の害を受けにくい | 宵鋼の装備一式: 攻め寄り。周りの Flux が濃いほど強い |
| 魔導アイテム | 光輪（頭）: 周りを照らし、虚空の残滓を寄せ付けない | 虚ろの外套（背）: 短い間、姿を消して攻撃をすり抜ける |

- 素材はどちらも、ランク 4 の Core（§4.6）・杖の金具と芯（§7.1）・装備に使う。容量は 8 以上
- 素材は大いなる注入の祭壇（§10.4）で作る。道の陣はランク 2 以上の Core で動く（どのランクかは着手するときに決める）

### 17.10 共通の終盤と Nihil の品（M5）

- どちらの道でも使う: Node（§11）、共鳴の台（無線輸送。§8.3）、大いなる注入の祭壇（§10.4）
